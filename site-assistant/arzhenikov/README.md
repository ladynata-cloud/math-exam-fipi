# Материалы для помощника курса Арженикова

Этот пакет привязывает подготовку помощника к опубликованным заданиям MathExam:
**6 маршрутов, 76 уроков и 608 условий**. Здесь находятся 76 опорных примеров и
24 отдельных проверочных ситуации. Условия взяты из существующих банков;
попытки и реплики учеников придуманы для испытания. Реальные работы детей
не читаются и не сохраняются.

Это подготовленные материалы, а не отчёт об обучении модели. Веса модели не
менялись. Kimi/OpenAI в создании этих новых ответов не вызывались. Опорный
ответ получает явную отметку `local-rules-reference`, а не имя модели.

## Что получает помощник

Вход содержит название и цель урока, точное условие, текущую модель, **один
текущий незавершённый шаг**, запись ученика и результат локальной проверки.
Готовые ответы, будущие шаги, вычислительные эталоны, объяснение полного решения
и целевые значения модели во вход не копируются. Контекст создаёт тот же
`ArzhenikovAssistantDialogue.context`, который используется в интерфейсе.

Каждый опорный пример относится к первому заданию своего урока. Проверочные
ситуации используют только задания самостоятельной проверки с индексом 4 или
выше. Пересечений идентификаторов заданий нет. Это **разделение по условиям**,
а не доказательство обобщения на неизвестные темы: уроки и типы навыков общие.

Проверочные случаи охватывают действия с целыми, смысл равных групп и остатка,
ноль в частном, преобразование десятичного делителя, действия с дробями,
разряды десятичных дробей, алгебру и геометрию. Отдельно проверяются верное
значение в неподходящей форме, неизменный знаменатель, просьба о готовом ответе,
недостаток контекста и признание уже проверенного верного решения.

## Воспроизводимая подготовка

Из корня репозитория, с Node.js 22 или новее:

```sh
node site-assistant/arzhenikov/materials.mjs manifest
node site-assistant/arzhenikov/materials.mjs references > references.jsonl
node site-assistant/arzhenikov/materials.mjs questions > questions.jsonl
node site-assistant/arzhenikov/materials.mjs rubric > evaluator-only.jsonl
node site-assistant/arzhenikov/materials.mjs offline > offline.jsonl
npm test --prefix site-assistant
```

Команды работают без ключа, сети и расходов. `manifest` фиксирует SHA-256
банков, контекстного модуля, движка и самого пакета. Повторная подготовка на тех
же исходниках даёт те же байты; время запуска в данные не добавляется.

| Экспорт | Назначение |
| --- | --- |
| `references` | 76 опорных примеров с ответами локальной программы; требуют педагогического просмотра. |
| `questions` | 24 входа модели с пользовательскими репликами, без рубрики и ожидаемых ответов. |
| `rubric` | Отдельные критерии и числовые ориентиры для проверяющего. Не передавать модели вместе с вопросом. |
| `offline` | Ответы действующих локальных правил на те же реплики; статус `evaluated:false`. |
| `manifest` | Состав, происхождение и хеши исходников. |

«Для проверяющего» означает отделение от входа модели, а не секретность файла
в открытом репозитории. Никакие закрытые критерии предыдущего эксперимента
сюда не переносились.

## Работа с Kimi и бонусным API

Kimi можно передать выбранные **публичные** опорные примеры и попросить
проверить математическую точность, понятность первого действия и отсутствие
готового итога. Полученный ответ нужно сохранить с датой, моделью/провайдером,
точным входом и хешами источников. Пока такого нового ответа здесь нет.

Для испытания OpenAI нужно использовать уже разрешённый бонусный проект.
Отдельный `run-evaluation.mjs` предназначен только для этих синтетических
вопросов. Ученическая страница его не загружает. Старая остановленная очередь
и её резервы не изменяются. Код и частные журналы прежнего эксперимента сюда
не переносились; транспорт нового запускателя проверяется отдельно.

В каждом контрольном случае начинается новый разговор. Поле `instruction`
задаёт роль, `context` — данные текущего шага, `turns` — последовательные
реплики пользователя. На следующем ходе должна использоваться реальная
предыдущая реплика проверяемой модели, а не ответ локальной программы или
выдуманная история. Продолжения заранее заданы, поэтому это проверка коротких
фиксированных сценариев, а не испытание адаптивного поведения ученика.

При сравнении вариантов следует закрепить одинаковые вопросы, контекст,
модель и параметры. Результаты перемешиваются для оценки; рубрика остаётся
отдельно. Не использовать эти же случаи как единственное доказательство
улучшения после исправлений по их результатам: затем нужны новые условия.

Оценка: по 0–2 балла за математику, работу с попыткой, понятный следующий шаг,
самостоятельность и ясность. Предложенный порог — не менее 8 из 10 и ни одной
критической ошибки в каждом случае. Пройденные программные тесты не выставляют
эти баллы и не доказывают полезность для реальных учеников.

Фактические ответы провайдеров, расход и решение о выпуске фиксируются
отдельно в отчёте задачи `ARZHENIKOV_ASSISTANT_20261124` и её PR.

## Ограниченное испытание OpenAI

По умолчанию запускатель **только показывает план**. Ни ключ, ни сеть, ни
папка результатов для этого не нужны:

```sh
node site-assistant/arzhenikov/run-evaluation.mjs --model gpt-6-luna
node site-assistant/arzhenikov/run-evaluation.mjs --model gpt-6.2-sol
```

Один запуск закрепляет одну из двух моделей. Для 24 случаев получается
28 последовательных запросов. Перед сетевой работой печатается полный план:
хеши исходников, модель, параметры, число запросов и резерв каждого запроса.
Ограничение — **не более $1 на отдельный запуск**, 32 обращений, 1024 выходных
токенов и 64 KiB сериализованного входа. Оценка входа консервативная: один
токен на байт UTF-8 плюс 1024 токена запаса; это инженерная граница, а не
официальный токенизатор.

На проверенных 23 ноября 2026 года (UTC) ставках резерв полного плана составляет
менее $0,04 для Luna и менее $1 для Sol. Точное значение выводит текущий план.
Ставки действуют для этого запускателя семь суток: с `2026-11-23T17:26:52Z`
до `2026-11-30T17:26:52Z` (верхняя граница не включена). `--run` проверяет
эту границу до создания папки и перед каждым запросом. Просроченная проверка,
дата раньше проверки и некорректные часы блокируют сетевую работу; обходного
флага нет. Для обновления нужно заново сверить официальные цены, пересмотреть
верхние ставки и даты в исходнике и повторить тесты/проверку кода. Просмотр
плана без `--run` остаётся доступен и после истечения срока.
Стандартные ставки: Luna — $0,10/$0,50; Sol — $2/$10 за миллион входных/выходных
токенов соответственно. Возможная запись кэша стоит дороже: поэтому **весь
вход** и при резервировании, и при расчёте результата считается по верхней
границе $0,125 для Luna и $5 для Sol за миллион. Это завышенная оценка расхода,
не выписка Billing. Ответ, который попадёт в следующий ход, ограничен 6 KiB
JSON-кодированной строки; превышение останавливает серию с удержанием резерва.
Источники: [официальные цены](https://developers.openai.com/api/docs/pricing),
[Luna](https://developers.openai.com/api/docs/models/gpt-6-luna),
[Sol](https://developers.openai.com/api/docs/models/gpt-6.2-sol).
Перед фактическим запуском оператор должен сверить действующие ставки и
**остаток и срок бонуса в выбранном проекте**. Ограничение $1 не проверяет
баланс кредитов и не ограничивает другие процессы или расходы всего аккаунта.
Совпадение проекта также не подтверждает наличие или срок действия бонуса.
Каждая новая папка результатов означает отдельный потенциально платный запуск
с собственным пределом $1; общего ограничения суммы нескольких запусков нет.

Для разрешённого запуска должны уже существовать `OPENAI_API_KEY` и
`OPENAI_PROJECT_ID`. Значение проекта должно буквально совпасть с отдельно
переданным `--bonus-project`; ключ не передаётся аргументом команды. Новый ключ
запускатель не создаёт. Пример формы команды, где `APPROVED_PROJECT_ID` заменяется
на заранее проверенный идентификатор бонусного проекта:

```sh
node site-assistant/arzhenikov/run-evaluation.mjs \
  --model gpt-6-luna --bonus-project APPROVED_PROJECT_ID \
  --out artifacts/arzhenikov-model-run --run
```

Родительская папка должна существовать, а `arzhenikov-model-run` — ещё нет.
Только флаг `--run` разрешает попытку. Неверный проект, отсутствующий ключ,
превышенный бюджет и неподдерживаемая модель останавливают программу до
создания папки и до сети. Произвольные адреса API и произвольные входные файлы
не принимаются. `--limit N` ограничивает испытание первыми N из 24 зафиксированных
ситуаций; это сокращённая выборка, которую нужно явно назвать в отчёте.

Запускатель использует Responses API с `store:false`, `service_tier:default`,
без инструментов и перенаправлений. Для Luna закреплено reasoning `none`,
для Sol — `low`. Неожиданная модель, тариф, некорректный учёт токенов,
незавершённый ответ или вызов инструмента блокируют продолжение.

Перед каждым запросом журнал и резерв записываются с `fsync`. В результатах
раздельно остаются фактический рассчитанный usage и неопределённый резерв.
При ошибке записываются безопасный код, числовой HTTP-статус, когда он получен,
и допустимый идентификатор запроса; тело ошибки, заголовки и секреты не пишутся.
Проверяется и отражение ключа или идентификаторов аккаунта в ответе провайдера:
такой request ID удаляется, а response ID или текст блокирует продолжение.
Привязка к проекту сохраняется как SHA-256, без исходного идентификатора.
Автоматических повторов нет. Папка и маркер блокировки остаются после успеха,
ошибки и прерывания: повторный запуск в ту же папку запрещён, продолжения
остановленной серии нет.

Вторую модель запускают отдельной явно выбранной серией после просмотра
первой. Ответы сохраняются со статусом `model-unreviewed`; автоматически
публиковать их или принимать в учебный корпус программа не умеет. Тесты
транспорта используют только подставные ответы и не считаются API-испытанием.
