с тегом canonical», но не содержит списка URL. Без авторизованного отчёта

Проверены 821 HTML-файл: 96 содержат canonical, 153 — noindex, пять —
meta-refresh. Во всём этом наборе не найдено canonical на отсутствующий

путями автоматический контроль охватывает 92 canonical и четыре refresh.

Реальные запреты индексации есть у `/school/` (`noindex,nofollow`), в том
числе старых маршрутов Виленкина 5/6 с `?course=…#course/…`, и у курса
Шестакова–Ященко. Это отдельная причина, не «Вариант страницы с canonical».
Существующая SEO-политика требует сохранять такие ограничения до решения
об открытии страниц. Для открытия старых маршрутов нужно отдельно определить
публичные входы и их содержание. Новый Виленкин 6, часть 1 уже имеет такой вход.

В базе аудита отдельного опубликованного входа в новый курс сечений не
найдено. Сечения представлены внутри действующих курсов. Неопубликованные
ветки не считаются страницами работающего сайта.

Восемь новых входов (Петерсон, Макарычев 7/8, Алимов, Никольский, два
учебника Атанасяна, Мерзляк) до исполнения JavaScript показывают главным
образом навигацию и загрузочную оболочку. Google умеет исполнять JavaScript,
поэтому это риск отображения и обнаружения содержания, не доказанный запрет.
Для уверенного вывода нужен отрендеренный HTML в URL Inspection. Отдельные
состояния `#задача` не создают самостоятельные страницы для sitemap.
В этот технический патч не включена переработка запечатанных реализаций курсов.

Эти строки показывают нормальные технические отношения между адресами.
Они **не подтверждены как строки конкретного отчёта Google от 22 октября**.
По справке Google статус Alternate page with proper canonical tag означает,
что альтернативная страница правильно ссылается на индексируемую основную;
для намеренного дубля исправление не требуется.

## Хостинг, robots и протокол

- `robots.txt`: `User-agent: *`, `Allow: /`, ссылка на правильный HTTPS sitemap.
- `https://www.mathexam.space/` возвращает 301 на `https://mathexam.space/`.
- `http://mathexam.space/` возвращает 200 без перехода на HTTPS, но с HTTPS canonical.
- `https://ladynata-cloud.github.io/math-exam-fipi/` возвращает 301 на
  `http://mathexam.space/`, затем 200.
- В проверенной публичной выборке не было заголовков `X-Robots-Tag` или
  HTTP `Link` canonical, противоречащих HTML.

Принудительный HTTPS следует отдельно проверить в GitHub Pages после
подтверждения сертификата. Сейчас HTTPS работает, а canonical уже выбирает
его. Отсутствие HTTP→HTTPS редиректа создаёт дополнительный протокольный
дубль, но не доказывает блокировку индексации. Это настройка хостинга;
подменять её JavaScript-переходами в этом патче не следует.

```text
                                                  PASS

```

Новые регрессии обнаруживают canonical с фрагментом, конфликтующие canonical
и несовпадение canonical с meta-refresh, включая страницы с noindex, которые
не попадают в sitemap. Сохранено исключение служебных/исходных файлов.
Существующие шесть тестов генератора также проходят. Независимая внутренняя
проверка не выявила блокирующих замечаний. Точные SHA и облачные запуски
помещаются в PR; локальный PASS не объявляется облачным PASS.

После авторизации в Search Console нужно открыть именно причину из письма,
получить примеры URL и для каждого сравнить: Google-selected canonical,
User-declared canonical, дату последнего обхода, текущий HTML/редирект,
входящие ссылки и sitemap. Текущая живая проверка и данные последнего обхода
Google могут относиться к разным версиям. Даже список примеров GSC ограничен
1000 адресами и не гарантирует полноты.
