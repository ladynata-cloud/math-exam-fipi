# Video Factory v1: подключение и работа

Video Factory — отдельное приложение. Оно не запускается внутри `mathexam-board`
и не использует его `/data`, поэтому тяжёлая сборка MP4 не мешает ученикам и
синхронизации прогресса.

## Что делает преподаватель

1. Открывает DVI-видеостудию и нужную задачу 18, 19 или 20.
2. Нажимает **Создать MP4**.
3. Выбирает один из трёх готовых вариантов, формат 16:9 или 9:16 и субтитры.
4. Один раз за вкладку вставляет ключ видеосервиса и запускает сборку.
5. Следит за состоянием `В очереди → Создаётся озвучка → Собирается видео` и
   нажимает **Скачать MP4**.

Ключ хранится в `sessionStorage`: он исчезает после закрытия вкладки, не входит
в адрес страницы и не попадает в ученические/учительские ссылки. Предпросмотр и
выгрузка текста озвучки работают даже при отключённом видеосервисе.

## Отдельное приложение Amvera

Создайте отдельное приложение из того же репозитория и точной принятой ветки.
Его сборка должна использовать `video-worker/Dockerfile`, а конфигурация —
`video-worker/amvera.yml`. Подключите постоянный каталог `/data`, один экземпляр
приложения и домен `video.mathexam.space`.

Обязательные переменные:

| Переменная | Значение |
| --- | --- |
| `NODE_ENV` | `production` |
| `VIDEO_ADMIN_TOKEN` | случайная строка не короче 32 символов |
| `VIDEO_ALLOWED_ORIGINS` | `https://mathexam.space,https://www.mathexam.space` |
| `VIDEO_STUDIO_URL` | `https://mathexam.space/trainers/dvi/math-18-20-video-studio.html` |
| `VIDEO_TTS_PROVIDER` | `openai` или `yandex` |
| `VIDEO_PERSISTENCE_CONFIRMED` | `1`, только после проверки постоянного `/data` |

Для OpenAI:

| Переменная | Значение |
| --- | --- |
| `OPENAI_API_KEY` | секретный серверный API-ключ |
| `OPENAI_TTS_MODEL` | по умолчанию `gpt-4o-mini-tts` |
| `OPENAI_TTS_VOICE` | по умолчанию `marin` |

Для Yandex SpeechKit:

| Переменная | Значение |
| --- | --- |
| `YANDEX_API_KEY` | секретный серверный API-ключ |
| `YANDEX_FOLDER_ID` | идентификатор каталога Yandex Cloud |
| `YANDEX_TTS_VOICE` | по умолчанию `alena` |

Защитные лимиты имеют безопасные значения по умолчанию и настраиваются через:

| Переменная | Значение по умолчанию |
| --- | --- |
| `VIDEO_MAX_PENDING_JOBS` | `4` |
| `VIDEO_MAX_JOBS_PER_HOUR` | `4` |
| `VIDEO_DAILY_TTS_CHAR_BUDGET` | `120000` зарезервированных символов в UTC-сутки |
| `VIDEO_MAX_OUTPUT_MB` | `500` на готовый ролик |
| `VIDEO_MAX_RETAINED_MB` | `4096` для готовых роликов |
| `VIDEO_MAX_WORK_MB` | `1024` временных файлов на одно задание |
| `VIDEO_COMMAND_TIMEOUT_SECONDS` | `180` на один запуск FFmpeg/ffprobe |
| `VIDEO_WORKER_LOCK_STALE_SECONDS` | `300`, больше максимальной внешней операции |
| `VIDEO_WORKER_LOCK_WAIT_SECONDS` | `360` ожидания при rolling deployment |
| `VIDEO_RETENTION_DAYS` | `30` |

Дополнительно обязательно установите жёсткий месячный лимит расходов у выбранного
TTS-провайдера. Лимит приложения уменьшает риск, но не заменяет ограничение в
OpenAI или Yandex Cloud.

Worker использует эксклюзивную блокировку на постоянном `/data`. Во время
rolling deployment новый контейнер ждёт освобождения блокировки и не начинает
повторную платную озвучку параллельно со старым контейнером.

## Проверка перед включением кнопки

1. `GET https://video.mathexam.space/healthz` возвращает `ok: true`.
2. Запрос без разрешённого `Origin` получает `403`, без ключа — `401`, а без
   корректного `Idempotency-Key` — `400`.
3. Тестовое задание проходит все состояния и скачивается как MP4.
4. После перезапуска приложения готовое видео остаётся доступным, а прерванное
   задание снова становится в очередь.
5. В журнале и JSON-файлах под `/data/jobs` отсутствуют ключи авторизации и TTS.
6. Во время сборки ученический прогресс DVI не меняется.
7. Параллельные POST-запросы не превышают лимит очереди, второй worker не может
   захватить тот же `/data`, зависший FFmpeg завершается по тайм-ауту, а
   переполненный диск переводит `/healthz` в fail-closed состояние.

Production rollout нельзя начинать, пока ADR 0002 остаётся Proposed. После его
принятия всё равно нужны точная авторизация merge/deploy и production smoke.
