Зафиксированы HTML, JavaScript, CSS, данные, изображения, необходимые справочные

наружу видимо обозначены «вне книги». У книжных копий есть `noindex` и исходный
публичный canonical.

Уточнены требования к путям файлов при фактической публикации: [сборка сайта
41143302786](https://github.com/ladynata-cloud/math-exam-fipi/actions/runs/41143302786/job/124362446779)
использует Jekyll. Он по умолчанию [пропускает имена с начальным
подчёркиванием](https://docs.github.com/en/pages/setting-up-a-github-pages-site-with-jekyll/about-github-pages-and-jekyll).
Служебная папка кандидата поэтому переименована из `_edition` в
`edition-assets`; глобальные настройки хостинга, книжные адреса и QR не изменены.
В проверку пакета добавлен запрет путей, исключаемых Jekyll. После изменения
повторно пройдены все 213 сценариев книжных копий: прежний прогон на обычном статическом
сервере сам по себе не подтверждал доступность служебных файлов после сборки.
Полная локальная сборка Jekyll не выполнялась: в среде нет Ruby/Jekyll или
контейнерного runtime. Проверка опубликованных байтов остаётся обязательной
после отдельного разрешения выпуска.

Необязательные облачные/досочные интеграции, аналитика и изменяемые загрузки
исключены из копий. У дорог по клеткам сохранён необходимый валидатор состояния,
регистрация в доске остаётся неактивной. Внешние шрифты заменены предусмотренными
исходным стилем системными запасными шрифтами.

`localStorage` и `sessionStorage` имеют отдельное пространство ключей книжной
редакции. Записи публичного тренажёра не копируются и не очищаются. Проверены
события между вкладками, именованные свойства хранилища и область действия
`clear()`. Результат хранится в этом браузере; синхронизация между устройствами
не заявляется. Блокировка или очистка хранилища пользователем ограничивает
сохранение обычным браузерным контрактом.

Проверка неизменности читает предыдущий манифест и реальные Git blob из базы PR.
Она запрещает изменение, удаление и добавление файлов в ранее опубликованную
редакцию, даже если одновременно переписать её манифест. CI также запускает
верификатор из базы, если он уже был опубликован. Для исправления опубликованной
книги потребуется новая версия пути. Защита относится к обычным проверяемым PR;
доступ администратора к хостингу остаётся организационной границей.

## Как проверить результат

Пользовательский XLSX содержит листы «Реестр», «Сценарии», «Ссылки и QR»,
«Исправления», «Основания». Статусы вычислены из первичных журналов без ручного
повышения `FAIL`, неизвестного или отсутствующего результата до `PASS`.
Архив доказательств содержит эти журналы, отдельные записи случаев, условия
и независимые ответы, исторические снимки runner и 34 QR. Для файлов проекта,
включая текущие runner и манифест, приведены точные Git-ссылки, blob и SHA-256;
проект не дублируется в архиве. Проверяющий скрипт отличает самостоятельную
проверку данных от проверки исходного кода с отдельным checkout указанного
commit. Хеши позволяют связать строку реестра с конкретным проверенным файлом.

Перенос результата после изменения пакета допустим только для неизменившихся
наблюдавшихся ресурсов с точным совпадением всех хешей. Затронутые страницы
пройдены повторно; исходные неудачные попытки и материалы независимого review
сохранены отдельно и не включены в успешные 426 случаев.

Новые книжные адреса должны быть опубликованы и проверены перед выпуском
кандидатных PDF/DOCX. При проблеме выпуска исходная публичная версия остаётся
доступной; исправления уже опубликованной книжной редакции оформляются новой
версией, а не скрытой заменой файла по печатному адресу.
