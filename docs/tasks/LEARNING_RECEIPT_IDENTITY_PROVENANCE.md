# Проверка идентификаторов в квитанциях учебного кабинета

**Задача:** самостоятельный остаток #385, без старой версии навигатора. **Владелец:** владелец MathExam. **Дата:** 2026-11-06. **Область:** MEDIUM, только тестовый код. **Ветка:** `test/receipt-identities-current-20261106`. **База:** `8d7fdd8c984a83213b1b4fddea371efc2a7f8c25`.

## Почему

Четыре цифры пароля могут случайно оказаться внутри корректного идентификатора или хеша. Исключить из проверки любое поле с именем id или learnerId недостаточно: туда можно поместить подставной ID или строку из вложенного пользовательского объекта. Переносим из исторического #385 только проверку происхождения известного поля, не его интерфейс, модель данных и формы кабинета.

## Что проверяется

Тест читает таблицы обезличенной временной SQLite, созданной этой же проверкой. В ответах допускаются исключения только для ожидаемого пути поля и совпадения с существующей записью попытки, назначения, фотографии, отзыва. Ссылка на фото должна точно соответствовать ID. Незапланированный ключ или значение со встроенным паролем по-прежнему отклоняется. При выдаче входа отдельная проверка связывает ID ученика с записью роли student и именно с выдавшим вход учителем. Старая проверка точной минимальной структуры квитанции выдачи и сохранности предыдущих квитанций оставлена.

Положительные и отрицательные фикстуры включают случайное совпадение цифр, неверный тип/путь/ID, подложный URL, несуществующую фотографию, чужого учителя и роль. Полный `node tools/learning-free-route.browser.cjs` проходит настоящий HTTP-сценарий учителя и ученика на локальной временной базе. Эти проверки не требуют чтения рабочих кабинетов и не подтверждают ничьих реальных персональных данных. Сравнение с исходной main ограничено тестом и данной спецификацией; откат обычным revert. Внешнее ревью не выполнялось по решению владельца.
