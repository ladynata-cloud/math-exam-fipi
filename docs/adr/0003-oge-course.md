# ADR 0003: Курс ОГЭ по образцу навигатора ЕГЭ

- Status: Accepted — решения приняты по поручению владельца 28.09.2026
  («прими все решения сама»); владелец может отменить любое из них
  отдельным решением до `START` соответствующей задачи.
- Date: 2026-09-28
- Decision owners: владелец сайта (Наталья Михайловна); подготовка — Claude
- Scope: раздел ОГЭ по математике: страницы курса, контракт прогресса,
  тренажёры линий 1–25, экзаменационный режим, входы с сайта
- Related: [план курса ОГЭ](../OGE_COURSE_PLAN.md),
  [контракт прогресса](../OGE_PROGRESS_CONTRACT.md),
  задачи `docs/tasks/OGE_COURSE_*.md`

## Context

У профильного ЕГЭ есть курс (`ege-profil/`): навигатор с живым прогрессом,
журнал ошибок, кабинет учителя с кодом прогресса `MEP1`, экзаменационный
режим и тесты уровня раздела. У ОГЭ — набор из ~40 тренажёров и страница со
ссылками `trainers/oge-course/`, которая прогресса не читает. Из линий 6–25
общий ключ `mathExamCourseProgress.v1` пишут семь тренажёров, шесть держат
свои ключи, шесть не сохраняют ничего, линия 15 — статичная страница.
Журнал ошибок в формате курса не ведёт ни один. Демоверсия ОГЭ-2027 (проект
ФИПИ от 26.08.2026) структуру не меняет, поэтому построенное под 2027 не
устареет.

Это не новый архетип: механика курса уже реализована и протестирована в
`ege-profil/`, контракт прогресса установлен кодом `ege-profil/registry.js`,
`progress-adapters.js` и тренажёрами `derivative-t8.html`,
`planimetry-yashchenko-t1.html`. ADR фиксирует, как этот образец применяется
к ОГЭ, и решения, которые раньше ждали владельца.

## Decisions

### 1. Дом курса — `/oge/`

Навигатор, журнал, кабинет и экзамен живут в `oge/` (`oge/index.html`,
`oge/review.html`, `oge/teacher.html`, `oge/exam/`). Адрес `/oge/` уже стоит
в шапке сайта и симметричен `/ege-profil/`. Текущая страница-список
`oge/index.html` заменяется навигатором. `trainers/oge-course/index.html`
становится редиректом на `/oge/`; три статичных разбора
`oge/algebra/task-09-linear-equations.html`,
`oge/algebra/task-14-sequences.html`, `oge/probability/task-10-probability.html`
и страница `oge/geometry/task-15-external-angle.html` — редиректами на
тренажёры своих линий, когда те готовы. Тренажёры остаются на своих адресах
в `trainers/`: на них есть ссылки у учителей.

### 2. Общий код страниц — копия в `oge/`, объединение позже

`registry.js`, `progress-adapters.js`, `progress-code.js`, `qr.js`,
`board-mirror.js` копируются из `ege-profil/` в `oge/` и адаптируются под
реестр ОГЭ. Подключать их из `../ege-profil/` нельзя: Code сейчас правит эти
файлы (#128, #130, #132), и связь через относительный путь ломала бы ОГЭ
при каждой правке ЕГЭ. Вынос в `assets/course/` с одним кабинетом на оба
курса — отдельная задача этапа 6 после стабилизации ЕГЭ. Тренажёры общий код
не подключают: тренажёр — один файл, работающий по `file://`.

### 3. Контракт прогресса — тот же, что у ЕГЭ

Ключ `mathExamCourseProgress.v1`; запись тренажёра `all[TID]`; журнал
`all.mistakes["TID|тип"] = { w, r, lastWrong, last }`; тип закрыт при `r >= 3`;
режим `?mode=review` даёт только открытые типы. Формат не расширяется и не
версионируется отдельно: один код `MEP1` переносит ОГЭ и ЕГЭ вместе.
Существующие TID (`oge-task16-circle`, `oge17-chetyrehugolniki`,
`oge18-kletki`, `oge23-vychisleniya`, `oge24-dokazatelstva`,
`oge25-geometriya`, `oge13InequalitiesSeries`, `practice*Trainer`,
`percentTableTrainer`) не переименовываются — иначе пропадёт прогресс
учеников. Новые TID — по схеме `oge-tNN-<slug>`. Идентификатор типа в
журнале — ключ типа самого тренажёра (`SUBS`, `S17`, `TYPES`, `MODULES`,
коды прогрессий), список закрепляется константой `TYPE_IDS` в тренажёре.
Полный текст — [OGE_PROGRESS_CONTRACT.md](../OGE_PROGRESS_CONTRACT.md).

### 4. Свои ключи мигрируют в общий, старые не удаляются

Тренажёры 10, 11, 12, 14, 19, 21 при первом открытии переносят счётчики из
своих ключей в свою ветку общего ключа один раз; старый ключ остаётся
нетронутым (откат без потерь). Заморозка №6 снимается (решение 8).

### 5. Ревью

`SMALL` — гейты и самопроверка исполнителя. `MEDIUM` — гейты, целевые
регрессионные тесты, заметки о риске и откате в PR. `HIGH` — дополнительно
независимое ревью точного head отдельной сессией Claude по образцу PR #96
(exact-head, с провенансом: PR, base SHA, head SHA, вердикт, дата). Запрет
внешнего ИИ-ревью из задачи `OGE_2027_ANALOGUE_DISTRIBUTE_1_5` на задачи
курса ОГЭ не распространяется. Merge по-прежнему только по отдельному
решению владельца для конкретного head.

### 6. Экзаменационный банк — собственные генераторы, независимый гейт

`oge/exam/bank.js` держит свои генераторы 25 линий (ядра переносятся из
тренажёров, не подключаются в рантайме), сид `mulberry32`, воспроизводимый
вариант. Каждая линия пересчитывается независимым кодом на точной
арифметике (`oge/tests/verify-bank.js`), тексты не содержат отпечатков
демоверсии (гейт как в `tools/oge-2027-analogue-1.test.mjs`). Авторский
аналог-2027 становится фиксированным «вариантом 0» пробника; его ключ
`mathExamOge2027Analogue1.v2` читается адаптером, миграция не нужна.

### 7. Пробник: шкала с пометкой, отдельный счёт по геометрии

`full-exam.html` показывает первичный балл 0–31, баллы по геометрии
(15–19, 23–25) отдельно и отметку по рекомендованной шкале Рособрнадзора
(«2» 0–7, «3» 8–14, «4» 15–21, «5» 22–31, для «3» и выше — не менее 2 баллов
по геометрии; письмо №04-44 от 18.02.2026) с подписью «рекомендованная
шкала, регион может отличаться; не официальный результат». Таблица `SCALE`
лежит в одном месте с ссылкой на источник. Часть 2 — самооценка 0/1/2 по
критериям с эталоном записи.

### 8. Задание 6: заморозка снимается

Ограничения из `OGE_TASK6_FRACTIONS_FOCUSED_FIX.md` (без хранения, без
лестницы, без классификатора ошибок) были ограничением той задачи, не
архитектурой. В задаче `OGE_COURSE_03F_TASK6` тренажёр получает генератор
выражений по типам, лестницу разбора, адресные ловушки и общий ключ. Банк
`TASKS` из 174 выражений остаётся режимом «по карточкам»; выражения — это
математика, а не текст КИМ, но любая прозаическая формулировка из карточек
ФИПИ переписывается своими словами. Тесты `oge-task6-fractions-focused.*`
и хеш-пин обновляются в том же PR.

### 9. Архивы «РешуОГЭ» и сканы листа КИМ

Архивные задачи в 16 (40), 17 (109), 18 (123), 23 (150) остаются режимом
«типы банка»: номера-источники сохраняются как ссылки, формулировки
переписываются своими словами там, где они дословно повторяют банк.
Встроенные base64-сканы листа справочных материалов в 16, 17, 18, 24
убираются; вместо них — собственный справочник, который в этих тренажёрах
уже есть (`REFS`, `PINS`). Это ещё минус 60–150 КБ в каждом файле.

### 10. Задание 19 — экзаменационный формат

Основной режим: три утверждения, ответ — номер истинного (как в КИМ 2027);
банк размечен по пяти темам; данные вшиты в файл (сейчас `fetch`, по
`file://` не работает). Система Лейтнера сохраняется как второй режим
«зубрёжка». Основа — `trainers/archive-5-weeks/oge19-source-aware-trainer-*`
(105 утверждений, 20 троек) плюс проверенные 63 утверждения `task19-data.json`.

### 11. Задание 15 — генераторный тренажёр по шаблону 16/17

Чертёж строится из чисел задачи, `auditFig`, адресные ловушки по значению.
Темы: углы треугольника и биссектрисы, равнобедренный, прямоугольный и
sin/cos/tg, площади, медианы и высоты, правильный треугольник. Основа — 37
генераторов `trainers/archive-5-weeks/oge15-trainer-v13-*`; их фиксированные
эскизы и ловушки-советы заменяются.

### 12. Задание 13 — новый генератор вместо серии из 26 задач

Линейные, квадратные (через рисунок), системы, «нет решений / любое число»;
везде выбор из четырёх, как в бланке. `trainers/oge-task13-inequalities.html`
перестаёт быть редиректом и становится тренажёром;
`oge13-inequalities-series.html` уходит в архив с редиректом.

### 13. Линия 1–5: единица прогресса «сюжет освоен»

Сюжет освоен, когда полный набор из пяти вопросов решён без помощи два раза
подряд; `solved/total` у всех сюжетов в этой единице; карта 1–5 и навигатор
читают одно и то же. `weakTopics` диагностики подсвечивают сюжеты на карте
и задают первый шаг маршрута. Новые сюжеты (ОСАГО, зонты, теплицы, террасы)
— по одному PR, состав сверяется с открытым банком ФИПИ на 2027.

### 14. Панель «Скачать и адаптировать» снимается с навигатора

Из трёх кнопок работает одна, готовые архивы из `downloads/` к панели не
подключены. Навигатор ОГЭ, как и ЕГЭ, панели не несёт; ссылки на готовые
архивы остаются на странице «Педагогам». Панели внутри самих тренажёров не
трогаются. `scripts/build-trainer-downloads.mjs` на новые тренажёры не
запускается.

### 15. Дубли уходят в архив с редиректом

`trainers/task14-progressions-trainer*.html` с их `.js/.css/.json` и корневой
`trainers/practice-1-5-tires.html` переносятся в `trainers/archive-5-weeks/`,
на старых адресах — редиректы; хабы и sitemap ведут на живые тренажёры.
Сначала (этап 0) унифицируются ссылки, перенос файлов — этап 6 вместе с
обновлением `downloads/trainers-manifest.json` и теста панели.

### 16. CI

Один workflow GitHub Actions на каждый PR: `npm test` в `oge/` и
`ege-profil/`, node-гейты из `tools/`, проверка ссылок. Фраза «CI ничего не
собирает и не тестирует» в `CLAUDE.md` обновляется тем же PR.

### 17. Приоритет — покрытие 25 линий раньше новых сюжетов 1–5

Линия 1–5 уже работает; без 13, 15 и 19 нет ни геометрического порога, ни
честного пробника. Порядок задач — в плане.

### 18. Язык и форма

Спецификации задач — по `docs/tasks/TASK_TEMPLATE.md`, по-русски, с
заголовками шаблона. Одна задача — одна ветка — один PR — явный `START`.

## Consequences

- Учитель получает один кабинет и один код прогресса на оба экзамена, а
  ученик 9 класса — тот же маршрут «диагностика → линии → журнал →
  пробник», что и одиннадцатиклассник.
- Тренажёры 7–25 меняются точечно (запись прогресса, журнал, ловушки,
  самопроверка), без переписывания: канон «не переписывать опубликованные
  тренажёры» соблюдается, кроме 13, 15 и 19, где текущие файлы — заглушки
  или не соответствуют формату экзамена.
- Хеш-пины и заморозки обновляются в тех же PR, что и правки: это
  осознанное решение владельца, зафиксированное здесь.
- Экзаменационный банк дублирует генераторы тренажёров; расхождение
  ловится независимым гейтом, а не связью в рантайме.
