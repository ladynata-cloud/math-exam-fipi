# Подготовка общего помощника для трёх сайтов

Дата задачи — 19 ноября 2026 года. База `main` — `d090b281822525aedf99ad7950f9288a345c85a4`. Ветка `codex/three-site-assistant-training`. Уровень проверки HIGH из-за расширения публичного HTTP-контракта. Исходная архитектура описана в [ADR 0011](../adr/0011-independent-assistant.md), первоначальный сервер — в [задаче о двух сайтах](TWO_SITE_DIALOGUE_20261119.md).

## Объём работы

Добавить в отдельный сервер MathExam третью роль для учебного сайта «Каббала и Таро». Существующие роли помогают в навигации MathExam, при делении и при чтении на «Узле тоски по миру». Расширить демонстрацию, клиент, обновление каталога и проверку источников. Приложить синтетические двухходовые диалоги с происхождением каждого примера и отдельными проверочными запросами. Объём поставки — черновик PR. Публикация сервера, обучение моделей, реальная переписка и тетради посетителей в эту задачу не входят.

## Проверка интеграции

- Один процесс обслуживает три значения `site`. Для каждой роли проверить локальный HTTP-ответ и повторную реплику в контексте активного сайта.
- Для каждой из 104 записей курса проверить ссылку на источник. При уточнении отличать текст автора от толкования курса. На запрос о личной тетради сообщить, где посетитель может открыть её самостоятельно.
- Убедиться, что отправка дополнительных закрытых полей и запрос с чужого origin отклоняются, а активные материалы не переходят между сайтами. При недоступности сервера уже подключённый сайт использует собственный механизм ответа.
- Проверить структуру трёх учебных наборов, связь строк с публичными источниками и отсутствие буквальных совпадений с вопросами из отложенного набора. Синтетические тесты дают базовую проверку поведения. Качество будущей модели оценивается отдельно.
- Из корня проекта выполнить `npm --prefix site-assistant test` и `git diff --check`. Проверку взаимодействия провести независимо от разработчика на реальных HTML/JS и локальном API. Внешний аудит у поставщика модели для этой задачи не запрашивался.

## Откат

Черновик не меняет production. При последующем выпуске адрес дополнительного сервиса можно убрать из конфигурации сайтов, а сервер вернуть на прежнюю версию обычным revert. Приложение не создаёт пользовательское хранилище и не требует миграции данных.

### Дополненный объём

- Исправленный поиск и новые литературные карточки поступают из отдельной задачи репозитория «Узла». Синхронизировать их штатным `sync:reader`, сохранив HTTP v1.
- Расширить три небольших набора авторскими диалогами; указать для каждой строки семейство ситуации, публичный источник, точную ревизию и относительные пути.
- Подготовить новые предметные контрольные задания отдельно от обучения и существующих шести проверок маршрутизации. Отделить входы модели от эталонов и рубрик.
- Сделать локальную проверку структуры, происхождения, ссылок, дубликатов, разделения вопросов и контрольных сумм. Подготовить повторяемую выгрузку пакета для передачи.
- Записать настоящий результат детерминированного сервиса на применимой части контрольных заданий; неподдерживаемые ситуации и смысловую оценку отметить явно.
- Подготовить инструкции будущему исполнителю: одинаковое испытание исходной и адаптированной модели, ручная проверка качества, ограничения данных и возвращение результатов.

### Приёмка и проверки

- Учебные строки содержат только `messages`, источники и служебные поля находятся отдельно. Реальная переписка, кабинеты и тетради не используются.
- Пакет собирается без сети и ключей, только из перечисленных файлов. Контрольные ответы не попадают в каталог загрузки для обучения.
- Изменение любого перечисленного файла делает старый manifest недействительным; существующий каталог выгрузки не перезаписывается.
- Сохранённые результаты модели проверяются на полную принадлежность текущему набору заданий; строковые проверки не объявляются доказательством педагогического качества.
- `npm --prefix site-assistant test`, `npm --prefix site-assistant run training:check`, воспроизводимая сборка пакета, `git diff --check`, независимый технический просмотр.
- Итоговый маркер подготовки: `THREE_SITE_PRETRAINING_PREPARATION_OK`. Он не означает обучения модели, публикации или готовности к занятиям с учениками.

### Границы разрешения

Прямое поручение разрешает реализацию, локальные коммиты, push существующей ветки и обновление Draft PR. Присланные владельцем в этом разговоре правила `AGENTS.md` требуют отдельного разрешения на merge и deployment; это ограничение сохраняется. Отправка данных поставщику, платные вызовы, запуск обучения, настройки учеников, личные данные и развёртывание сервера не входят в подготовку. Новая архитектура платного публичного сервиса не вводится; принятый ADR 0011 не превращает публичный сервер в закрытый `assistant-service/`.

### Обзор и риски

Уровень остаётся HIGH. Независимый агент проверяет исходники и готовый набор; это внутренний технический просмотр, а не отзыв внешнего поставщика. Главные риски — ложное распознавание произведения, утечка эталона в запрос, недостоверная атрибуция источника и принятие форматного теста за измерение качества. Все данные синтетические; поведение реальных учеников ещё не исследовано. Результаты и не выполненные проверки фиксируются в [отчёте подготовки](../reports/THREE_SITE_PRETRAINING_20261119.md).
