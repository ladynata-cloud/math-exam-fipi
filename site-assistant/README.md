# Общий сервер читательского и математического помощников

Один процесс обслуживает поиск по MathExam, подсказку к текущему действию при делении и разговор о книге на «Узле тоски по миру». Ответы формируются правилами тренажёра и проверенными карточками мастерской. Для запуска достаточно Node.js 22 или новее. Вызовов модельных API, базы данных и сохранения реплик в приложении нет.

## Запуск и проверка

Из корня репозитория:

```sh
npm start --prefix site-assistant
```

Откройте `http://127.0.0.1:8080/`. На этой странице можно попробовать оба помощника и отправить вторую реплику. Проверка состояния доступна по `/healthz`. Команда `npm test --prefix site-assistant` поднимает временный HTTP-сервер для проверок и завершает его после тестов. Загрузка npm-пакетов не требуется.

Для отдельного хоста можно собрать контейнер командой `docker build -f site-assistant/Dockerfile -t site-assistant .` **из корня репозитория**, затем запустить `docker run --rm -p 127.0.0.1:8080:8080 site-assistant`. Файл Docker использует модули из `assets/assistant/`. Для коробочной поставки вместе с `site-assistant/` нужны `assets/assistant/navigator-data.js` и `assets/assistant/division-dialogue.js` на тех же относительных путях.

## Подключение сайтов

Выделите приложению HTTPS-адрес. Общий сервер можно размещать отдельно от кабинетов Amvera. Существующий закрытый `assistant-service/` имеет собственные сессии и настройки.

| Переменная | Значение |
| --- | --- |
| `HOST`, `PORT` | По умолчанию `127.0.0.1` и `8080`. В контейнере `HOST=0.0.0.0`. |
| `SITE_ASSISTANT_PUBLIC_ORIGIN` | Точный внешний адрес самого сервера, например `https://dialog.example.org`, для демонстрации на этом же хосте. |
| `SITE_ASSISTANT_MATH_ORIGINS` | Дополнительные адреса страниц MathExam через запятую. Основной адрес — `https://mathexam.space`. |
| `SITE_ASSISTANT_READER_ORIGINS` | Дополнительные адреса «Узла» через запятую. Основной адрес — `https://usel-toski-po-miru.art`. |

Адреса указываются со схемой, без пути и завершающей косой черты. Для локальной проверки подходят HTTP-адреса `127.0.0.1` и `localhost`. Происхождение проверяется по браузерному заголовку Origin и выбранному сайту. Обычный программный клиент, например проверочный скрипт, может обращаться без Origin. Сервис предназначен для общедоступных данных, не использует cookie и не требует персонального токена. Один экземпляр принимает до 1200 запросов диалога в минуту; при расчёте нагрузки за обратным прокси учитывайте число экземпляров.

`GET /client.js` выдаёт браузерный клиент. При настройке укажите настоящий адрес сервера; браузер вызывает `POST /api/v1/dialogue` на том же адресе. До подключения публичного сервера страницы работают локально. Для другого Node-приложения экспортирована функция `createHandler()` из `server.mjs`, возвращающая обработчик Node HTTP.

## Протокол v1

В теле запроса передайте `site`, одну текущую реплику `message`, объект `context` и при необходимости `state` из предыдущего ответа. Длина реплики — до 500 символов, всего тела — до 8192 байт. В ответе есть `version`, `site`, текст `reply`, ссылки `links` с полями `id, label, url` и новое `state`. Ссылки берутся из справочника навигатора и карточек чтения. Навигатор может также возвращать `kind` и предложенные действия `actions`. Чтобы начать сначала, опустите `state`.

| Сценарий | Пример `context` |
| --- | --- |
| Выбор тренажёра на MathExam | `{"surface":"navigator","pathname":"/"}` |
| Текущий шаг деления | `{"surface":"division","step":"digit","partial":37,"divisor":6}` |
| Читатель вспоминает произведение | `{"surface":"reader","mode":"before_reading"}` |
| Читатель сам выбирает обсуждение прочитанного | `{"surface":"reader","mode":"after_reading","workId":"work-yushka"}` |

Для первых двух строк `site="mathexam"`, для остальных `site="uzel"`. В делении `step` заимствуется из текущего действия плана тренажёра. `divisor` — положительный целочисленный делитель после нормализации, `partial` — текущее неполное делимое. Можно передать `attempt` от 0 до 9 и исходные десятичные строки `dividend`, `originalDivisor`. Готовое решение в запрос не входит. В литературном режиме не загружайте разборы до явного решения обсудить прочитанное. В качестве `workId` подставьте идентификатор выбранной безопасной ссылки из первого режима. Помощник может сослаться на первичный источник или обозначить предел проверенного текста.

Пример первого запроса:

```sh
curl -s http://127.0.0.1:8080/api/v1/dialogue \
  -H 'Content-Type: application/json' \
  --data '{"site":"uzel","message":"незаметное добро","context":{"surface":"reader","mode":"before_reading"}}'
```

Скопируйте `state` ответа в следующий запрос, сохраняя тот же `context`, а в `message` напишите «Помню горницу». Ответ укажет карточку «Матрёниного двора». В приложении передавайте состояние как непрозрачный объект и сбрасывайте его при смене задачи, сайта или разговора. Ошибки HTTP возвращают объект `{"error":"код"}`.

## Обновление читательских материалов

При запуске используются включённые в репозиторий правила и 21 пара карточек. Интернет для чтения этих данных не нужен. Чтобы обновить их, соберите текущий репозиторий `ladynata-cloud/uzel-toski-po-miru` командой `SITE_URL=https://usel-toski-po-miru.art python3 build.py`. Затем из корня MathExam выполните:

```sh
npm run sync:reader --prefix site-assistant -- /absolute/path/to/uzel/dist
npm test --prefix site-assistant
```

Синхронизация берёт `dist/assets/reader-search.js`, поля первого чтения и соответствующие им записи второго из `dist/assistant/v1/`. Сопоставление идёт по `card_id`. При расширении подборки увеличится число пар. Полный литературный каталог остаётся на сайте «Узла». Возраст, авторство текстов, ссылки и ограничения сверки берутся из мастерской. Результаты тестов описывают поведение программы на подготовленных примерах; оценить будущую модель можно на тех же примерах в отдельном испытании.
