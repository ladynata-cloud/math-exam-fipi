# Планиметрия-1: порог зачёта, самопроверка, коллизия ловушек

## Идентификация

- Задача: под общим TID `ege-t1-planimetry-generator` три страницы ставили
  `passed=true` при любом счёте зачёта/марафона — карта курса и кабинет учителя
  показывали «зачёт сдан ✓» даже при 0 из 8. Самопроверка курса
  `runSelfTest` крутилась при каждой загрузке у каждого ученика и молчала.
  В шаблоне 1 (равнобедренный, дан угол при основании) при x = 45 две ловушки
  давали одно число, и ученик получал сообщение не про свою ошибку.
- Владелец: ladynata-cloud (Наталья Михайловна)
- Дата: 2026-09-26
- Базовая ветка: `main`
- Базовый SHA: `be2740b` (Панель скачивания больше не сжимает тренажёр на телефоне, #131)
- Ветка: `fix/planimetry-t1-pass-threshold`
- Уровень ревью: `MEDIUM` — поведение записи прогресса в трёх тренажёрах,
  подпись адаптера на карте курса и в кабинете, данные шаблонов задач.
- Ревью 26.09.2026: две важные находки (P1-A, P1-B), две мелкие (P1-C, P1-D)
  и четыре замечания (F1–F4) — все воспроизведены и отработаны, см. «Ответ на
  ревью».
- Связано: `docs/tasks/PLANIMETRY_GENERATOR_BEST_MINUS1.md` (#130, «давний
  дефект: зачёт сдан ✓ при любом счёте» — там вынесен как отдельный вопрос);
  курс профильного ЕГЭ `ege-profil/` (#114, #128).
- ADR: не применяется.

## Цель

Ученик, сдавший зачёт по заданию 1, видит «зачёт сдан ✓»; ученик с 5 из 8 —
честный лучший результат и порог, который надо взять. Учитель в кабинете
различает сданный зачёт и попытки — и у новых, и у старых записей.
Подсказка нигде не стоит зачёта. Самопроверка курса запускается только по
`?selftest=1`, печатает маркер и сама ловит коллизии ловушек во всех шаблонах.
Ловушка в диагностике либо адресна, либо её нет: два разных неверных хода не
дают одно число, ни один неверный ход не даёт верный ответ, и ни одно
сообщение ловушки не называет ответ.

## Контекст и факты

Проверено по коду на базе `be2740b`.

1. Писатели TID `ege-t1-planimetry-generator`: курс
   `ege-profil/trainers/planimetry-t1.html` («Зачёт», `EXAM_N=8`),
   `trainers/ege-t1-planimetry-trainer.html` (копия курса: до правки
   отличалась тремя строками в `numSubmit`, после — теми же тремя) и
   `trainers/ege-t1-planimetry-generator.html` («Марафон», `MARATHON_N=8`;
   копии `downloads/trainers/ege-t1-planimetry-generator/…html` и html внутри
   `…-package.zip`, побайтно равные друг другу).
2. `journal('finish',{score})` во всех трёх: `st.best=Math.max(st.best||0,score)`,
   `st.passed=true` безусловно. Счёт — число задач, решённых чисто: в курсе
   `okAns` с одной попытки без подсказок (в зачёте их нет), в генераторе
   точки `'g'` (0 ошибок, 0 подсказок, без показа решения).
3. Адаптер `planimetry` в `ege-profil/progress-adapters.js`: `passed===true` →
   полная полоса «зачёт сдан ✓» с `done`, иначе «запусков: N». Его читают
   карта курса `ege-profil/index.html` (`data-progress="planimetry"`) и
   кабинет `ege-profil/teacher.html` (реестр `CABINET` в `registry.js`,
   `PROGRESS.apply`). Соседние адаптеры без сдачи пишут «зачёт: N из 10»
   (`plan1y`) и «зачёт: N из 7» (`vec2y`).
4. Порог сдачи у соседей курса — полный счёт: Ященко-1 «сдан при 10 из 10»
   (`planimetry-yashchenko-t1.html:1541`), векторы 7 из 7, производная —
   `EX.score >= 8` из 8 (`derivative-t8.html:887`).
5. Самопроверка курса (`runSelfTest`, до правки строки 1964–1993) выполнялась
   при каждой загрузке и при ошибке писала `console.warn('SELFTEST FAILED')`
   без маркера. Проверяла RECOG, GUIDES, HLMAP, CONSTRUCT; ловушки не
   проверяла. Образец режима `?selftest=1` с маркером — `selfTest()` в
   `ege-profil/trainers/pryamougolny-treugolnik-trenazher.html`
   (`RIGHTTRI_SELFTEST_OK` / `_FAIL`).
6. Ловушки в `diag` — замыкания с цепочкой `if(eq(v, …)) return …`, отдельного
   списка значений нет; `genOne` оборачивает `diag` так, что совпадение с
   ответом возвращает `null` (общая фраза). Совпадение ловушки с ответом
   значит: неверный ход даёт верный ответ и засчитывается.
7. Разбор всех вариантов всех восьми шаблонов (подтверждено прогоном нового
   харнесса на копии файла со старыми данными: 54 уникальных дефекта на
   2000 генераций каждого шаблона):

     дефект); дан угол при вершине: y = 90 → `y` и `180−y` оба 90;
   - тип 2, дан угол C: y = 90 → `y` и `180−y`; кроме того ловушка `90−y/2`
     тождественно равна первой (`(180−y)/2`) при любом y — недостижимая строка;
     дан внешний угол: e = 120 → ответ 60 = `180−e` = `e/2`, и `e` = `180−e/2`;
   - тип 3, «на d° больше»: d = 30 → «вычел d из 90°» даёт 60 — верный ответ;
   - тип 4, катеты: (5,20), (6,12), (8,8), (12,6) → `2(a+b) = ab/2`, «периметр»
     равен площади;
   - тип 5, Пифагор: тройки 6-8-10 и 5-12-13 — периметр равен площади
     (24 и 30), «периметр» совпадал с ответом;
   - тип 6, вписанный/центральный: вариант a при x = 60 → `180−x` = ответ
     120; вариант b при y = 60 (`2y` = `180−y`), y = 90 (`y` = `180−y`),
     y = 120 (`180−y` = ответ 60);
   - тип 8, дуги 1 : 2 : 3 → дуга 180°, угол 90° = `180−ответ`.
   Типы 3 (вариант «в k раз»), 4 (остальные пары), 6 (вариант d), 7 —
   чистые. Те же шаблоны с теми же коллизиями стоят в генераторе (см. «Риски»).
8. Гейт `tools/ege-t1-planimetry-generator-hub.test.mjs` выполняет `renderHub`
   генератора через `new Function` с фиксированным списком имён; новая
   константа внутри `renderHub` требует её инъекции в гейт.
9. `zipfile` при записи подменяет `external_attr=0` на `0o600<<16`; сжатые
   потоки уровня 6 совпадают с архивом побайтно, атрибут возвращён до
   записи каталога — пересборка без правки воспроизводит исходный zip
   побайтно.
10. (Ревью, P1-A.) В генераторе `setControls` прятал `#hintBtn` только в
    разборе (`view==='demo'`), в марафоне кнопка была видна; `dotClass`
    считает `load = mistakes + hints`, и задача с одной подсказкой — жёлтая
    (`'y'`), она не входит в `good`. До правки это ни на что не влияло
    (`passed` ставился безусловно); с порогом 8 из 8 одна подсказка делала
    зачёт недостижимым: 8 верных с первой попытки + 1 подсказка →
    `finScore` «7 / 8», `passed` не ставился. Воспроизведено в Chrome.
11. (Ревью, P1-B.) На базе `passed=true` ставился при любом счёте, поэтому у
    каждого ученика, хоть раз дошедшего до финала зачёта или марафона, стоит
    `passed:true` при любом `best`. Инвариант писателей после правки:
    `best = max(best, score)`, `passed` только при `score ≥ 8` ⇒ у честно
    сданного зачёта всегда `best ≥ 8`. Значит, запись `{best:3, passed:true}`
    может быть только старой, и её отметка ничего не подтверждает.
    Воспроизведено: карта курса, кабинет, хабы курса и генератора и строки
    итога показывали «зачёт сдан ✓» при `best:3`.

## Педагогические решения (по поручению «реши сам»)

**Порог зачёта — все 8 из 8 чисто** (`EXAM_PASS = EXAM_N = 8`,
`MARATHON_PASS = MARATHON_N = 8`), а не 6 из 8.

1. В зачёте каждый из восьми типов задания 1 встречается ровно один раз.
   Счёт 7 из 8 — не «шероховатость», а пробел в конкретном типе, и один и тот
   же тип может проваливаться из раза в раз; страница сама указывает на него
   маршрутом «что подтянуть». Порог ниже полного выдал бы «сдан» ученику с
   устойчивым пробелом, и маршрут рядом с «сдан» противоречил бы сам себе.
2. Задание 1 — 1 балл, одноходовые и двухходовые задачи. На экзамене оно
   либо решено, либо нет; «почти» не оценивается. Пересдача бесплатна и
   занимает несколько минут.
3. Так же устроены соседи курса: Ященко-1 сдан при 10 из 10, векторы при
   7 из 7, производная при 8 из 8. Учитель читает «зачёт сдан ✓» в кабинете
   одинаково по всем линиям.
4. **Марафон генератора — зачёт без подсказок, как «Зачёт» курса** (ответ на
   P1-A). Зачёт курса подсказок не имеет с самого начала; в марафоне кнопка
   «Подсказка» была доступна, а задача с подсказкой не считалась чистой —
   с порогом 8 из 8 подсказка стоила бы зачёта, что прямо нарушает канон
   «Подсказки ничего не отнимают». Выбран вариант «скрыть», а не «не учитывать
   подсказку в счёте»: во втором случае точка задачи оставалась бы жёлтой
   («с одной шероховатостью»), а зачёт — сданным, и ученик видел бы два
   разных ответа на один вопрос «чисто ли решено». Теперь `setControls` прячет
   `#hintBtn` при `state.typeIdx<0`, `giveHint` в марафоне не срабатывает,
   карточка марафона говорит «в экзаменационном темпе, без подсказок. Зачёт
   сдан при 8 из 8 чисто: верный ответ с первой попытки», первая задача
   марафона — «Марафон без подсказок, как на экзамене». В тренировке типа
   (4 задачи) подсказки остаются, и после возврата из марафона кнопка снова
   видна. Кнопка «Показать решение» в марафоне не трогается: она появляется
   после двух ошибок, когда задача уже красная, и ничего не отнимает.

**Сданный зачёт не отзывается**: `passed` пишется только `true` и никогда не
сбрасывается. **Хранилище не мигрируется, но отметка читается вместе с
`best`** (ответ на P1-B): «зачёт сдан ✓» показывается только при
`passed === true && best ≥ 8` — в адаптере (`cnt(st.best) >= PLAN_EXAM_N`),
в хабах курса и генератора и в строках итога. Ни одна честно заработанная
отметка не теряется (у неё `best ≥ 8` по инварианту писателей), а старая
запись `{best:3, passed:true}` показывает честное «лучший зачёт: 3 из 8» /
«лучшее: 3 / 8» без ✓. Первоначальное решение «старые записи не трогать
вообще» отклонено: оно оставляло заявленный дефект у всех существующих
учеников, а «отметку поставили не по вине ученика» не аргумент — отметка
ничего не подтверждала. Само поле `passed` в записи не меняется: стоит
ученику сдать зачёт, `best` станет 8 и отметка появится.

**Честная обратная связь вместо «пройден!»**: полоса финала различает
«✓ Зачёт сдан: 8 из 8!» и «Зачёт завершён: N из 8. Сдан при 8 из 8 — маршрут
ниже»; строка итога — «Лучший зачёт: N / 8 · зачёт сдан ✓» либо «· сдан при
8 из 8»; карточка зачёта в хабе называет порог и добавляет «· зачёт сдан ✓»
только при `passed` и `best ≥ 8`. Адаптер без сдачи пишет «лучший зачёт:
N из 8» (полоса N/8, без `done`), как соседние «зачёт: N из 10». Полоса и
строка итога объявляются вслух (`aria-live="polite"`, F2): с этой правкой
их текст несёт смысл «сдан / не сдан».

**Коллизии ловушек — устранены в данных, не в сообщениях**: значение, при
котором два неверных хода совпадают, исключено из генерации (как уже было
сделано с x = 60), а данные, при которых неверный ход даёт верный ответ,
заменены. Иначе слабый ученик получал бы упрёк не за свою ошибку или
«верно» за неверный приём. Тройки 6-8-10 и 5-12-13 заменены на 15-20-25 и
10-24-26 (вычисления √(625−225)=20, √(676−100)=24 — того же уровня); набор
дуг 1 : 2 : 3 — на 4 : 5 : 6 (дуги 96°, 120°, 144°, все чётные). Разбор
типа «Пифагор» по-прежнему показывает 6-8-10, разбор типа «дуги» — 1 : 2 : 3:
в разборе ловушек нет. Недостижимая ловушка `90−y/2` слита с первой:
«Это ВНУТРЕННИЙ угол ABC (то же самое, что 90° минус половина ∠C)…» —
словами, а не формулой «90° − ∠C : 2», которую слабый ученик читает как
(90° − ∠C) : 2 (P1-C).

**Сообщение ловушки не называет ответ** (P1-D): в типе 6 (вариант «на d°
больше») ловушка `d/2` говорила «получается x = d°» — в режиме «Сам решаю»
ученику оставалось перепечатать число. Теперь: «Половина здесь не появляется.
Уравнение 2x = x + d°: убери по x с обеих сторон — что останется справа?» —
через смысл (чаши весов), а не через приём «перенеси», по канону «понимание
раньше приёма». Остальные сообщения курса проверены: ответа не называют.

**Самопроверка — только по `?selftest=1`**: 2000 генераций на шаблон — это
55–67 мс на десктопе и 64–83 мс на телефоне (Chrome, два прогона), но
ученику она не нужна, а молчащий `console.warn` никого не спасал. Маркер
`PLANIMETRY_T1_SELFTEST_OK` / `PLANIMETRY_T1_SELFTEST_FAIL` со списком
дефектов; localStorage не трогается.
Ловушки не дублируются списком: `EQ_SPY` перехватывает каждое
`eq(v, ловушка)` внутри сырого `diag` шаблона при зондировании
значением-сигналом, поэтому проверка не разойдётся с кодом при добавлении
ловушки. Ловушка со значением ≤ 0 отключена своим условием (`…&&90−x>0`) и в
счёт не идёт.

## Риски и откат

- Основные риски: ученики, привыкшие видеть «пройден!» при любом счёте,
  увидят «Сдан при 8 из 8» — это и есть цель. Ученик со старой записью
  `{best:3, passed:true}` перестанет видеть ✓ — отметка не подтверждала
  сдачу; поле в записи сохраняется, после честных 8 из 8 отметка вернётся.
  Ученик генератора, привыкший к подсказке в марафоне, её не найдёт —
  карточка и первая задача об этом говорят, в тренировке типа подсказка
  осталась. Замена троек и набора дуг меняет числа задач, не тип и не
  уровень.
- Откат: revert squash-коммита; записи прогресса совместимы в обе стороны
  (поля те же).
- Совместимость данных: старый `passed:true` читается как сданный только
  вместе с `best ≥ 8`; новые записи без 8 из 8 поля `passed` не имеют —
  адаптер и хабы показывают «лучший зачёт: N из 8».
- Известный дефект вне объёма (для отдельной задачи «Планиметрия-2»):
  шаблоны генератора `trainers/ege-t1-planimetry-generator.html` (и двух его
  копий) — тот же код, что в курсе до правки: коллизии x = 45, y = 90 (типы 1
  и 2), e = 120, d = 30, пары катетов с (a−4)(b−4) = 16, тройки 6-8-10 и
  5-12-13, x = 60 и y ∈ {60, 90, 120} у вписанных углов, дуги 1 : 2 : 3,
  недостижимая ловушка `90−y/2` и сообщение ловушки `d/2` типа 6 с ответом
