# Передача помощников в обучение

## Что передаётся

Подготовлены три отдельные роли: MathExam, читательский помощник «Узла тоски по миру» и помощник по символам и источникам «Каббалы и Таро». Это материалы для небольшого контролируемого эксперимента. Весов обученной модели, измеренного улучшения и работающего модельного API в пакете нет.

Исходные `train-*.jsonl` — авторские синтетические диалоги. В них нет записей учеников, кабинетов и личных тетрадей. Карточки сайтов дают ограниченный контекст: они не заменяют полные тексты книг и не доказывают правильность любой произвольной математической подсказки. Подробности происхождения и ограничения — в `DATASET_CARD.md`, `provenance.jsonl`, `source-pins.json` и `manifest.json`.

## Как устроен собранный пакет

| Каталог | Назначение |
| --- | --- |
| `upload-training/` | Только три файла обучения. Выбрать нужную роль; не загружать пакет целиком. |
| `evaluation-inputs/` | Одинаковые новые вопросы для исходной и будущей модели. Использовать после фиксации учебной версии. |
| `review-only/evaluation/` | Ожидаемые свойства ответа и рубрики для проверяющего. Не подставлять в запрос модели и не добавлять в обучение. |
| `review-only/` | Происхождение, ограничения, инструкции и контрольные суммы. |
| `knowledge/` | Публичные снимки каталога и материалов, с которыми подготовлены примеры. |
| `offline-toolkit/` | Самостоятельная копия сервера и скриптов проверки с исходными данными. Нужен Node.js 22+, установка зависимостей не требуется. Весь этот каталог также не загружается в обучение. |

Входы и эталоны проверки хранятся раздельно, но находятся в одном репозитории для воспроизводимости. Поэтому это редакционно отложенная выборка, а не секретный независимый экзамен. После исправлений по её результатам она становится регрессионным набором; для следующего честного сравнения нужны новые вопросы.

## Порядок будущего эксперимента

1. Зафиксировать точную ревизию пакета, SHA-256 manifest, поставщика, идентификатор модели и реально поддерживаемый способ адаптации. Возможны инструкции и поиск по базе либо изменение весов модели. Назвать выполненный способ точно.
2. До платного запуска определить максимальную сумму/число запросов, лимиты входа и ответа. Проверить актуальную официальную документацию выбранного поставщика: наличие режима обучения, формат строк и правила обработки данных. Этот пакет сам не предоставляет разрешения на расходы или передачу данных.
3. Сначала прогнать **исходную модель** на `evaluation-inputs/inputs.jsonl` с тем же контекстом, который будет доступен адаптированной. Сохранить её ответы, модель, параметры и время запуска. Эталоны в запросы не передавать.
4. Для первой итерации выбрать одну роль и небольшой учебный набор. Отложенные задания не использовать ни для обучения, ни для подбора подсказок. Поставщик может требовать отдельный validation-набор; не выдавать итоговый контрольный набор за validation. При необходимости составить дополнительные авторские примеры для validation до эксперимента и зафиксировать новую версию.
5. Повторить те же контрольные входы с адаптированной моделью. Импортировать сохранённые ответы локальным скриптом проверки. Отсутствующие ответы и неподдержанные режимы фиксировать, а не заполнять эталонами.
6. Сравнить ответы вручную, по возможности в перемешанном виде без названий моделей. Автоматический отчёт проверяет только явно перечисленные свойства. Корректность рассуждения, педагогический такт, спойлеры и верность источнику требуют смыслового просмотра.
7. Вернуть результаты по каждому случаю, список ухудшений и затрат. Если исходная модель с контекстом уже справляется не хуже, отдельно зафиксировать, что дообучение пока не принесло измеримого выигрыша.

## Что считать полезным результатом

**MathExam.** Помощник использует фактически переданную попытку, не выдумывает состояние доски, предлагает выполнимый следующий шаг. При нехватке условия уточняет. Арифметика и объяснение верны. Полный ответ не появляется раньше запроса на разбор. Допустимые альтернативные преобразования уравнения не объявляются ошибкой.

**«Узел».** Название и автор выбираются по достаточным основаниям. Известный автор с неизвестным названием не приводит к подмене другой книгой. Неоднозначное воспоминание вызывает уточнение. До чтения сохраняется безопасный контекст; после чтения комментарий мастерской отличён от авторской цитаты. При доступности только фрагмента не делаются выводы обо всём произведении.

**«Каббала и Таро».** Различаются изображение, исторический источник, конкретная традиция и учебная интерпретация. Символическое прочтение не превращается в установленный факт или обещание будущего события. Помощник не приписывает себе чтение личной тетради. Точный источник предпочтительнее выдуманной цитаты.

Повторяющиеся уверенные математические ошибки, ложное авторство/цитирование, систематические спойлеры или обещания действий в чужом кабинете блокируют публичный запуск. Единого процента «качества» из автоматических строковых проверок недостаточно. На этом этапе не измеряется образовательный эффект на учениках.

## Что вернуть владельцу

- Поставщик, точная модель, способ адаптации, версия данных и все параметры запуска.
- Отдельные файлы ответов baseline и candidate с исходными ID; пропущенные и отклонённые задания указаны явно.
- Отчёты автоматической и ручной проверки; хорошие ответы, ошибки и ухудшения по одинаковым вопросам.
- Фактические расходы и длительность, если выполнялись оплачиваемые операции.
- Рекомендация по следующему небольшому испытанию. Подключение модели к публичным сайтам — отдельная работа после проверки.

Результат детерминированного сервера можно использовать как третью точку сравнения. Он не является ответом исходной языковой модели и должен оставаться помеченным `runtime` / `offline-rules`.
