# Проверка идентификаторов в квитанциях учебного кабинета

**Задача:** завершить существующий PR #470, самостоятельный остаток #385, без старой версии навигатора. **Владелец:** владелец MathExam. **Дата:** 2026-11-06. **Уровень проверки:** HIGH, поскольку проверяется защита доступа и конфиденциальных данных; изменение остаётся только тестовым. **Ветка:** `test/receipt-identities-current-20261106`. **Исходная база:** `8d7fdd8c984a83213b1b4fddea371efc2a7f8c25`. **База повторной проверки:** `47059d1e808186dea8df08a030a8dea85a145b84`.

## Почему

Четыре цифры пароля могут случайно оказаться внутри корректного идентификатора или хеша. Исключить из проверки любое поле с именем id или learnerId недостаточно: туда можно поместить подставной ID или строку из вложенного пользовательского объекта. Переносим из исторического #385 только проверку происхождения известного поля, не его интерфейс, модель данных и формы кабинета.

## Что проверяется

Тест читает таблицы обезличенной временной SQLite, созданной этой же проверкой. В ответах допускаются исключения только для ожидаемого пути поля и совпадения с существующей записью попытки, назначения, фотографии, отзыва. Ссылка на фото должна точно соответствовать ID. Незапланированный ключ или значение со встроенным паролем по-прежнему отклоняется. Автор операции должен существовать в accounts. При выдаче входа проверяются роль teacher автора, роль student получателя, связь получателя с выдавшим вход учителем и точная минимальная структура квитанции. Проверка сохранности предыдущих квитанций оставлена.

Положительные и отрицательные фикстуры включают случайное совпадение цифр во всех поддерживаемых полях идентификаторов, неверный тип/путь/ID, несовпадение полей с сохранённой записью, подложный URL, несуществующую фотографию, чужого учителя и роль. Неизвестные ID проверяются как с цифрами PIN, так и без них: отсутствие PIN не должно скрывать ошибку происхождения. Неверные квитанции должны вызывать именно AssertionError; случайный TypeError не считается доказательством работы защиты.

## Утверждённые границы

- Изменяются только этот документ и `tools/learning-free-route.browser.cjs` в существующем PR #470.
- Рабочий сервер, интерфейс кабинета, схема БД, реальные ученики и их результаты не изменяются. Это регрессионный барьер CI, а не новый фильтр HTTP-запросов.
- Полный браузерный сценарий продолжает выполняться по умолчанию. Дополнительный `--receipt-guard-only` позволяет отдельно проверить фикстуры без запуска браузера и не заменяет обязательный полный сценарий.
- Основание выполнения и выпуска — прямой запрос владельца завершить, исправить при необходимости и объединить PR после успешных проверок, а также [действующая политика публикации](../OWNER_RELEASE_AUTHORIZATION.md). Внешний аудит не запрошен; независимое техническое ревью и применимые проверки обязательны.

## Критерии и проверки

- Корректные непрозрачные ID со случайным совпадением цифр PIN принимаются только в подтверждённых местах. Подставные и неверно связанные ID, фото, URL, поля с секретом и некорректные квитанции отклоняются.
- Учитель выдаёт доступ нужному ученику, сохраняет собственную сессию; ученик входит с выданными данными. Повтор запроса не создаёт второй аккаунт и не заменяет пароль.
- Назначения, исходное условие, введённые ответы, этап решения, отправленная работа и результаты сохраняются после навигации, перезагрузки, нового входа и восстановления базы.
- Проверяются изоляция другого синтетического ученика, корректная работа фотографий, повторная сдача и отклонение устаревшего отзыва преподавателя.
- Команды: `node tools/learning-free-route.browser.cjs --receipt-guard-only`, полный `node tools/learning-free-route.browser.cjs`, `npm --prefix board-server test`, `node tools/learning-onboarding-rollback.cjs`, `node --check tools/learning-free-route.browser.cjs`, `git diff --check`.
- Обязателен свежий GitHub Actions для кандидата с актуальной main: Unified learning (включая HTTP/Chromium/SQLite, онбординг и production-container) и OGE basics. Старые зелёные запуски не заменяют эту проверку.
- Независимая проверка мутациями намеренно убирает отдельные условия защитного теста и проверяет, что фикстуры обнаруживают ослабление.

## Риски и откат

Проверки относятся к синтетическим данным и проверенному коду, не являются аудитом реальных кабинетов, инфраструктуры или всех возможных атак. Откат — обычный revert двух файлов; миграции, удаление данных и откат ученических результатов не требуются. Перед объединением повторно сверяются авторитетные main/head; после него проверяются родитель коммита, точный набор файлов, blob-идентичность и patch ID. Статус публикации не следует из текста этой спецификации.
