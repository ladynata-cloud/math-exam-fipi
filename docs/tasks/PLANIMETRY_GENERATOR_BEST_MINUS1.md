# Генератор планиметрии (задание 1): не показывать «лучшее: -1»

## Идентификация

- Задача: хаб генератора `trainers/ege-t1-planimetry-generator.html` показывает
  на карточке типа «лучшее: -1 / 4», если ученик начинал этот тип в курсе
  или в `trainers/ege-t1-planimetry-trainer.html` и ошибся.
- Владелец: ladynata-cloud (Наталья Михайловна)
- Дата: 2026-09-24
- Базовая ветка: `main`
- Базовый SHA: `d5c9d0388ab3b22bcffec10d11504a0624e2b598`
- Ветка: `fix/planimetry-generator-best-minus1`
- Уровень ревью: `SMALL`
- Связано: курс профильного ЕГЭ в `ege-profil/` (PR #114); решение владельца
  №3 при слиянии архива курса — планиметрия «-1» идёт отдельным PR.
- ADR: не применяется.

## Цель

Ученик, который начал тип задания 1 в курсе и ошибся, открывает генератор и
видит на карточке этого типа «ещё не тренировался», а не «лучшее: -1 / 4».
Настоящие результаты серий (0…4 из 4) показываются как раньше; записи курса и
тренажёра под общим TID не теряют ни одного поля.

## Контекст и факты

Проверено по коду на базе `d5c9d03`.

1. Под TID `ege-t1-planimetry-generator` в `mathExamCourseProgress.v1` пишут три
   страницы: генератор, курс `ege-profil/trainers/planimetry-t1.html` и
   `trainers/ege-t1-planimetry-trainer.html`.
2. Курс и тренажёр заводят `types[i] = {best:-1, hist:[], mastery:0, err:0, recogErr:0}`
   в `bumpTypeStat` (уже при первой ошибке, `err:1`) и в `setTypeSeries`.
   Там -1 значит «серий по типу ещё не было»; собственный хаб курса это
   учитывает (`s.best!=null && s.best>=0`).
3. Генератор в `bestBadge` считал «не тренировался» только `best==null`,
   поэтому показывал «лучшее: -1 / 4».
4. Размеры совпадают: `TYPE_N=4` на всех трёх страницах, `MARATHON_N=8` в
   генераторе = `EXAM_N=8` в курсе; первые 8 типов курса идут в том же порядке,
   что `TYPE_META` генератора, — индексы `types[i]` согласованы.
5. Запись генератора после серии: `tt.best=Math.max(tt.best||0, good)`.
   `-1||0` даёт -1, но `good ≥ 0`, поэтому итог серии всегда ≥ 0 — -1 как
   результат серии не сохраняется, правка записи не нужна. Поля `mastery`,
   `err`, `recogErr` и чужие записи генератор не трогает.
6. Верхний `st.best` (бейдж марафона) пишется только через `journal`:
   `Math.max(st.best||0, score) ≥ 0`. От наших страниц -1 туда не попадает,
   но код прогресса MEP1 (`ege-profil/progress-code.js`) кладёт объект «как
   есть», поэтому бейдж марафона тоже проверяет, что это число ≥ 0.
7. До правки нечисловое значение `best` из хранилища вставлялось в
   `innerHTML` хаба как есть (строка `<img src=x onerror=…>` исполнялась бы).
8. Копии: `downloads/trainers/ege-t1-planimetry-generator/ege-t1-planimetry-generator.html`
   (тот же файл без download-панели) и он же внутри
   `…/ege-t1-planimetry-generator-package.zip` (совпадал побайтно).
   `scripts/build-trainer-downloads.mjs` не запускается — он переписывает
   исходники и ломает `file://`; копии правятся точечно.

- Те же две строки в downloads-копии и в html внутри zip; вторая запись архива

- Гейт `tools/ege-t1-planimetry-generator-hub.test.mjs` (голый Node).
- Эта спецификация.

### Вне объёма

- Курс `ege-profil/trainers/planimetry-t1.html` и
  `trainers/ege-t1-planimetry-trainer.html`: их формат с `best:-1` остаётся.

- «лучшее: 0 / 8» на карточке марафона, когда марафона не было (запись
  заводится с `best:0`), — поведение до правки, не меняется.
- Вёрстка download-панели рядом с тренажёром (см. «Риски»).
- Запуск `scripts/build-trainer-downloads.mjs`.

- Любые файлы, кроме пяти перечисленных ниже.

Изменяемые файлы: `trainers/ege-t1-planimetry-generator.html`,
`downloads/trainers/ege-t1-planimetry-generator/ege-t1-planimetry-generator.html`,

## Критерии приёмки

- [x] `bestBadge(null)`, `bestBadge(-1)` → «ещё не тренировался»; `0` →
  «лучшее: 0 / 4»; `3` → «лучшее: 3 / 4»; `4` → класс `g`.
- [x] Мусор (`NaN`, `Infinity`, строки, объекты) не попадает в разметку хаба.

  «ещё не тренировался», карточка 2 — «лучшее: 3 / 4», ошибок консоли 0.
- [x] После серии в генераторе `types[0]` = `{best:3, hist:[3], mastery:0, err:1, recogErr:0}`:
  чужие поля, `types[1]`, другие TID и старые события сохранены.
- [x] Три копии генератора содержат одинаковые `bestBadge` и `renderHub`.
- [x] В html-файлах изменены ровно две строки и добавлена одна строка
  комментария; переводы строк (CRLF) сохранены.
- [x] Архив: `unzip -t` без ошибок, запись промпта побайтно прежняя,

## Риски и откат

- Основные риски: минимальные. Для настоящих результатов (целые 0…4 и 0…8)
  отображение не меняется. Запись в хранилище не менялась.
- Откат: revert squash-коммита; данных и настроек не затрагивает.
- Совместимость данных: старые записи с `best:-1` просто показываются как
  «ещё не тренировался»; миграция не нужна.
- Давний дефект, не исправляется в этой задаче: «зачёт сдан ✓ при любом
  счёте». `journal('finish')` в курсе (`planimetry-t1.html`), в
  `ege-t1-planimetry-trainer.html` и в самом генераторе ставит
  `st.passed=true` безусловно — после зачёта или марафона из 8 задач даже со
  счётом 0 / 8. Адаптер `planimetry` в `ege-profil/progress-adapters.js`
  при `st.passed` рисует полную полосу «зачёт сдан ✓» — на карте курса
  (`ege-profil/index.html`) и в кабинете учителя (`ege-profil/teacher.html`).
  Порог зачёта не определён; нужен отдельный вопрос владельцу.
- Давний дефект вёрстки, не из этой задачи: у генератора `body{display:flex}`,
  а download-панель, дописанная сборщиком загрузок, стоит соседом `.app` в
  одном ряду. На 1280 px тренажёру остаётся 671 px, на 360 px — 155 px,
  карточка марафона обрезается. Скачиваемая копия (без панели) выглядит
  нормально.
