## Goal and evidence

Сделать работу внутри существующих заданий понятнее: собственная попытка, помощь по конкретному затруднению, сохранённый разбор и проверка на другом условии. Карта курса из PR #496 уже доступна: 9 ноября публичные `course-journey.js` и `path/task-first.js` побайтово совпали с текущей основой. Эта проверка двух ресурсов не означает повторную приёмку всего сайта.

Аудит текущего кода: 111 типов используют общий task-first; для всех отсутствуют авторские карты ошибочных ответов, поэтому чаще показывается общая рекомендация. Подбор невстречавшегося условия действовал только для четырёх семейств уравнений. Модели долей и цифр могли сохранять сообщение о верном результате после изменения выбора.

Педагогические основания: короткое действие перед объяснением; точечная помощь с сохранением правильных частей работы; модель для проверки зависимости; самостоятельное похожее задание после разбора. Это адаптация наблюдений, а не утверждение о проверенном эффекте на учениках или полном копировании закрытых интерфейсов других сайтов.

- Общий учебный цикл всех 111 типов личного курса: обратная связь, последовательное раскрытие помощи, заметный следующий шаг после решения.

## Review, risks and rollback

Уровень HIGH обусловлен общим движком и сохранением состояния. Независимый агент проверяет учебную логику, математические границы, совместимость и итоговый diff. Внешний платный аудит не запрашивался и не проводится; педагогический эффект в реальном занятии ещё не измерен.

Главные риски: ложный самостоятельный зачёт, потеря черновика, несовместимое восстановление модели, перенос личного поведения на общую доску. Старые поля и версия остаются совместимыми, новые поля ограничены и проверяются. Откат — обычный обратный коммит интерфейса без удаления ученических сохранений. Новый allowlist поля `model.discovery` необходимо оставить в валидаторе: прежний строгий валидатор отвергает незнакомые поля модели. Полный слепой revert валидатора несовместим с уже сохранёнными прогнозами. Остальные необязательные task-first поля прежним кодом игнорируются. Перед слиянием сверяются актуальные main/head и тестируемая композиция; после — родитель, дерево, Pages и публичные ресурсы.
