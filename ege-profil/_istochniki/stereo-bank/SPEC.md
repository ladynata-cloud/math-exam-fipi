## Объединённый банк (с 24.09.2026)

Банк линейки `ege-profil/trainers/stereo` — два набора задач в одном
`js/data.js` (его собирает `sync-data.js`):

| набор | файлы | id | сцена | задач |
|---|---|---|---|---|
| старый — открытый банк задания 3 (Решу ЕГЭ) | `problems-legacy-<slug>.js`, массивы `P_LEGACY_<SLUG>` | номер задачи на Решу ЕГЭ, только цифры | `scene.prims` или `dims`, строит `engine-legacy.js` | 143 |
| новый — по типовым моделям | `problems-<slug>.js`, массивы `P_<SLUG>` | `<slug>-NN` | `scene.bodies`, строители `engine.js` | 138 + 7 «Развёрток» |

- **Старые задачи: id, условие, ответ, подсказка, решение и порядок не
  правятся.** Они перенесены из опубликованной линейки
  `trainers/ege-profile-stereometry-3d` (коммит 4dc0592); под их id
  у учеников записан прогресс (`stereo3.status`), под позицией в теме —
  `stereo3.last.<тема>`. Их особенности (ответ `1,125` у 27118, короткие
  подсказки-формулы) перечислены в `_check.js` как допустимые.
  Исключения — решение владельца 24.09.2026, только для линейки курса:
  у задач из списка `SCENE_FIXED` в `legacy-parity.js` исправлен чертёж
  (`scene`, `labels`, `construct`), у задач из списка `UNIT` добавлено поле
  `unit`. Новое исключение — только вместе с записью в эти списки
  и зелёными воротами.
- **`unit`** (только старые задачи): длина в единицах условия на единицу
  сцены, если сцена нарисована в масштабе k ≠ 1 (условие даёт только объём
  или площадь; радиусы 6, 8, 10 нарисованы как 0,6; 0,8; 1). Панель
  измерений показывает `fmtLen(длина на сцене · unit)`; верно unit = 1/k.
  Значение — точным выражением (`10`, `90/11`, `Math.cbrt(16/(12*Math.PI))`).
  Новым задачам unit не нужен: их сцена строится в единицах условия.
- **Старый формат, дополнения движка:** `scene.segs: [[P, Q], …]` —
  отрезок данных условия (диагональ), видимый сразу, рисуется ребром тела;
  `scene.pts: {имя: [x, y, z]}` — вспомогательная точка первого тела
  (координаты старого формата), чтобы подписать отрезок из условия; имя
  с «_» — без буквы и кружка (центр сечения конуса у 324454, 525721);
  у части конуса (`keep`) обод основания рисуется дугой, точки P, Q целого
  конуса в вырезе не рисуются (`engine.js`, `sceneDataFromLegacy`).
- **Новый формат, часть конуса:** `sector: {ts, tl, part: true}` — нарисована
  часть конуса (а не только часть боковой поверхности, как в «Развёртках»):
  обод основания — дугой над тем же сектором (kon-23, kon-24).
- **`fmtLen`** (панель измерений): целое — «n»; если длина x = √m для целого
  m ≤ 100 000 с допуском по самой длине |√m − x| ≤ 1e-9·max(1, x) — корень
  в школьной записи с вынесенным множителем: «2√2», «2√3», «√5»; иначе —
  до сотых (сотые считаются целым числом, без погрешности float), с запятой.
- **Построение (`construct`)** должно что-то добавлять на сцену: точку,
  закраску, новый отрезок или подпись. Отрезок построения, совпавший с уже
  нарисованной линией (ребро, ось, радиус), второй раз не рисуется: тренажёр
  выделяет эту линию цветом построения и показывает подпись построения, если
  линия не подписана уже в `labels`. Построение из одних таких отрезков без
  подписей не показало бы ничего — `legacy-parity.js` проверяет это у всех
  288 задач.
- **Порядок.** В каждой теме сначала старые задачи в исходном порядке, потом
  новые: `PROBLEMS = [].concat(P_LEGACY_KUB, P_KUB, P_LEGACY_PAR, P_PAR, …, P_RAZV)`.
- **Дубли.** Пять новых задач повторяли старые (та же модель, те же числа)
  и убраны: `kub-11` (= 27081), `par-36` (= 245363), `priz-03` (= 27082),
  `kon-17` (= 27160), `komb-07` (= 27051). Номера оставшихся не сдвигались,
  на месте убранных — комментарий; их верификаторы проверяют, что дубль
  не вернулся.
- **par-34** переписана своими словами (числа, ответ и сцена те же): прежнее
  условие дословно повторяло текст задания демоверсии.
- Новую задачу проверь на пересечение со старыми: та же модель с теми же
  числами — это дубль, а не новая задача.
- Ворота объединённого банка: `sync-data.js`, `_check.js --all` (размер

## Задание для автора нового набора

Ты пишешь один тематический фрагмент банка для готового 3D-движка.
Движок и обвязка уже написаны и проверены — твоя работа только данные.

## Что сдать

В папке банка (`_istochniki/stereo-bank/`):

1. `problems-<slug>.js` — файл вида:
   ```js
   const P_<ИМЯ> = [ {…задача…}, {…задача…}, … ];
   ```
   Ничего кроме этого массива в файле нет. Кириллица — только через
   инструмент Write или python-скрипт с encoding='utf-8', НЕ через bash heredoc.

2. `verify-<slug>.js` — независимый верификатор (см. раздел «Верификация»).

## Формат задачи

```js
{
  id: "<slug>-01",            // префикс = slug, номера по порядку
  topic: "<Тема>",            // ровно как в задании, одна на весь файл
  group: "объём",             // короткий подтип (виден в шапке навигации)
  cond: "Текст условия…",     // ЧИСТЫЙ ТЕКСТ, без HTML (выводится как textContent)
  ans: "48",                  // строка; целое или конечная десятичная дробь,
                              // не более 2 знаков после запятой; запятая: "1,5"
  scene: { bodies: [ …тела… ] },
  labels: [ ["A","B","4"], ["A","C1","?"] ],   // подписи длин на рёбрах (опц.)
  givenFaces: [ {face:["A","B","C","D"], text:"S = 36"} ],   // грань с данным (опц.)
  construct: { … },           // анимация построения (опц., см. ниже)
  hint: "Одна-две фразы, подталкивающие к идее, БЕЗ ответа.",
  sol: [ "Строка решения 1.", "Строка 2." ]   // 2–4 строки, можно ²³·−√ и <b>…</b>
}
```

Правила содержания:
- Формулировки — заново, по типовым моделям первой части ЕГЭ. Ничего не
  копировать дословно ни из каких сборников. Стиль ФИПИ: коротко, сухо,
  без сюжетной воды; единицы измерения либо отсутствуют, либо согласованы.
- π в ответ не попадает никогда: либо «Найдите V/π», «Найдите S/π»,
  либо отношение величин, где π сокращается.
- Корни в ответ не попадают: если величина иррациональна — спрашивай
  её КВАДРАТ («Найдите квадрат диагонали») или подбирай пифагоровы числа
  (3-4-5, 5-12-13, 8-15-17, 7-24-25, 20-21-29 и кратные им).
- Числа выбирай так, чтобы промежуточные шаги тоже были опрятными.
- «?» в labels ставь на искомый отрезок, если искомое — отрезок.
- Не менее трети задач темы — с блоком construct (диагонали, сечения,
  высоты, апофемы), там, где построение реально поясняет решение.
- group используй, чтобы разложить тему на 3–6 подтипов.

## Тела сцены (kind + параметры)

Все координаты — в ЕДИНИЦАХ ЗАДАЧИ (настоящие длины!), y — вверх.
Это принципиально: после верного ответа движок показывает длину любого
кликнутого отрезка, поэтому геометрия обязана быть честной.
Общие опции любого тела: `at:[x,y,z]` (сдвиг), `ghost:true` (призрачное),
`hideLabels:true`, `coordLabels:[{t:"h", p:[x,y,z], q:[x,y,z]}]` — выносная
подпись у середины отрезка p–q (для r, h круглых тел).

- `{kind:"box", a, b, h, names?:["A","B","C","D"]}` — параллелепипед
  a(по x) × b(по z) × h(высота). Вершины: низ A,B,C,D и верх A1…D1.
- `{kind:"lshape", footprint:[[x,z],…], faceRects:[[x0,z0,x1,z1],…], h,
   names:["A",…]}` — прямая призма над прямоугольным многоугольником
  (все двугранные прямые). faceRects — разбиение основания на
  прямоугольники, ОБЯЗАТЕЛЬНО покрывающее его точно. Вершины низа — names
  по контуру, верх — с суффиксом 1.
- `{kind:"prism", n, side|R, h, names?}` — правильная n-угольная призма
  (n = 3, 4, 6); либо `{kind:"prism", base:[[x,z],…], h}` — прямая призма
  над произвольным многоугольником (например, прямоугольный треугольник).
- `{kind:"pyramid", n, side|R, h, apex?:"S"}` — правильная пирамида;
  либо `base:[[x,z],…]` + `apexAt:[x,y,z]`.
- `{kind:"cyl", r, h, centers?:["O","O1"], axis?:true,
   rim?:{A:{ang:-1.9, at:"bot"|"top"}}, gens?:[["A","A1"]],
   water?:{h}}` — цилиндр; water рисует воду до уровня h.
- `{kind:"cone", r, h, flip?:true, apex?:"S", center?:"O", axis?:true,
   rim?:{A:{ang}}, water?:{h, r}, sector?:{ts, tl}}` — конус;
  flip — вершиной вниз (сосуд); water — конус воды (только с flip);
  sector — нарисована только часть боковой поверхности (углы в радианах).
- `{kind:"sphere", R, center?:"O", at?:[x,y,z], rim?:{A:{ang}},
   section?:{y, name?}}` — шар; по умолчанию лежит на плоскости
  (центр [0,R,0]); section — оранжевая окружность сечения на высоте y
  от центра (r сечения движок посчитает сам).
- `{kind:"custom", pts:{}, faces:[], edges:[], circles:[], surfaces:[]}` —
  на крайний случай (дополнительные окружности сечений и т.п.).

Сосуды с водой делай `ghost:true` — иначе вода не видна сквозь стенку.
Комбинации тел: внешнее тело ghost, внутреннее обычное (или наоборот),
центры совмещай через `at`.

У КАЖДОЙ задачи должна быть содержательная сцена с настоящими размерами
из условия. Если в условии даны V или S, а рёбра неизвестны — строй тело
с фактическими размерами, которые получаются в решении.

## construct (анимация построения)

```js
construct: {
  points: { "M": ["mid","A","B"], "K": [0.5, 1, 0.5] },
  segments: [ ["A","C"], ["A","C1","?"] ],   // третий элемент — подпись
  fills: [ ["A","C","C1"] ],                 // полупрозрачная заливка
  solid: [ …кольцо… ]                        // «дышащая» заливка
}
```
Точка `["mid",P,Q]` — середина PQ. Числовая тройка — доли габаритов
ПЕРВОГО тела kind:"box" в сцене ([доля a, доля h, доля b]); если боксов
в сцене нет — это обычные координаты в единицах задачи.

## Верификация (обязательная, в духе курса)

`verify-<slug>.js` пересчитывает ответ КАЖДОЙ задачи независимо от данных
сцены: числа он берёт регулярками ИЗ ТЕКСТА cond (как это принято в этом
проекте — проверяем от условия, а не от генератора), применяет свою
формулу по модели задачи и сравнивает с ans через parseAns с допуском 1e-9.
Соответствие «id → модель» захардкодь в верификаторе.

Загрузка банка в node:
```js
const api = require("./_load.js")("./problems-<slug>.js", "P_<ИМЯ>");
// api.PROBLEMS, api.parseAns, api.sceneData, api.fmtLen
```
Дополнительно верификатор обязан проверить геометрию сцены против условия:
если в условии «ребро равно 4», то расстояние между соответствующими
точками сцены (из api.sceneData(p): gen[i].pts) равно 4 с допуском 1e-9.
Проверь так ВСЕ числа условия, которым соответствуют отрезки сцены.
Вывод: `OK <N> задач, расхождений 0` и exit 0, иначе список расхождений и exit 1.

## Ворота качества (прогнать самому, до сдачи)

Из папки `banks/`:

```bash
node _check.js problems-<slug>.js P_<ИМЯ> "<Тема>" <число>   # структура
node verify-<slug>.js                                        # математика
bash topic-run.sh <slug> P_<ИМЯ> "<Тема>"                    # Chromium
```

Прогон в Chromium снимает скриншот каждой задачи в `banks/shots-<slug>/`.
ПОСМОТРИ каждый скриншот глазами (инструментом Read) и доведи сцены:
подписи не должны налезать друг на друга и уезжать за край, тело — стоять
по центру, «?» — висеть на искомом отрезке, вода — быть видна. Типовые
лекарства: подписи на разные рёбра одной длины; rim-точки в разные углы
(ang по кругу); coordLabels вместо labels у круглых тел; поворот
основания rot; другой выбор именованных вершин.

Все три ворот зелёные + скриншоты пересмотрены — только тогда сдавай.
В отчёте: числа всех трёх ворот, сколько скриншотов пересмотрел и что
поправил по итогам, список моделей с ответами НЕ прикладывай.
