# Первая выборка для MathExam и «Узла тоски по миру»

Здесь 30 авторских диалогов для пробного дообучения общего помощника. В каждом из них посетитель задаёт вопрос и продолжает разговор после первого ответа. Источники — открытые учебные материалы и каталог мастерской. Реплики придуманы для проекта.

| Файл | Содержимое и назначение |
| --- | --- |
| [train-math.jsonl](train-math.jsonl) | 15 примеров. Подсказка к попытке ученика, поиск материалов, выбор уровня ВПР, уточнение условия. |
| [train-reader.jsonl](train-reader.jsonl) | 15 примеров. Выбор между карточками, поиск без результата, чтение без спойлеров, обсуждение прочитанного и проверка источника цитаты. |
| [provenance.jsonl](provenance.jsonl) | Для каждой строки указан сайт, номер строки в соответствующем учебном файле, постоянный ID и источник. |
| [eval.jsonl](eval.jsonl) | Контроль для проверяющего. 16 отдельных разговоров, по восемь на сайт. Для каждой из 21 реплики указаны критерии и ошибки, которые нужно отметить. |

### Подготовить файлы

В корне репозитория выполните команды с Node.js 22 или новее. Они работают без ключей и подключения к поставщику моделей.

```sh
npm test --prefix site-assistant
node site-assistant/scripts/preflight.mjs train > train.jsonl
node site-assistant/scripts/preflight.mjs questions > questions.jsonl
node site-assistant/scripts/preflight.mjs offline > offline.jsonl
```

В объединённый `train.jsonl` входят только два перечисленных учебных файла, сначала математический. В нём 30 объектов `messages` и 60 целевых ответов. Сверьте формат многоходового диалога с выбранной обучающей платформой перед передачей. Для раздельных экспериментов можно брать исходные файлы соответствующего сайта.

### Сравнить три варианта ответа

1. **Ответы программы по правилам.** Команда `offline` воспроизводит каждый контрольный разговор, передавая состояние только внутри него. Сохраняются показанный текст и ссылки. Этот результат позволяет проверить, какую помощь сайты уже дают сами.
2. **Исходная модель.** Возьмите `questions.jsonl`. Номер строки соответствует строке в `eval.jsonl`. В начале каждого случая откройте новый диалог. Передайте как системный контекст поля `system`, `context` и, если есть, `evidence`. Затем отправляйте строки из `turns` **по одной**, дожидаясь ответа. Вторая реплика должна видеть первый ответ именно этого собеседника. Служебный номер и название сценария модели не нужны.
3. **Та же модель после обучения.** Повторите испытание на тех же вопросах, версии каталога и параметрах генерации. Сохраните идентификаторы моделей, ревизию репозитория, настройки и ответы со ссылками. Критерии и список недопустимых ошибок остаются у проверяющего. Если случаи использовались для правки примеров после просмотра ответов модели, подготовьте также новые вопросы для заключительной оценки.

В навигационных заданиях модель видит доступные названия и адреса. При поиске книги по воспоминанию ей выдаются все 21 карточка первого чтения. При обсуждении открытой работы доступен её разбор с ограничениями источника. Явная просьба о чтении без спойлеров оставляет только безопасный материал.

### Как выставлять оценку

Перемешайте варианты ответов и скройте название модели. Для каждой реплики запишите одну оценку и короткое обоснование. **2** — выполнено требуемое действие. **1** — ответ помогает частично. **0** — он уводит в неверную сторону или пропускает нужное действие. Ошибку из поля `forbidden` отметьте отдельно и сохраните фразу или ссылку, по которой её можно проверить. Подведите результаты отдельно по каждому сайту. На такой выборке важны конкретные исправления и ухудшения.

### Что показал первый прогон по правилам

Уточнение уровня ВПР сохраняет ранее названный класс. Программа находит «Тоску» по Ионе и Чехову, различает её со «Студентом», возвращается к завязке «Уроков французского» по просьбе читать без спойлеров и указывает первоисточник для сверки слов Лескова. Сравнение заголовков с фамилией автора и переходы по карточкам проверены на копии «Узла» из [PR №14](https://github.com/ladynata-cloud/uzel-toski-po-miru/pull/14). Открытие новых якорей на публичном сайте зависит от выпуска этой версии литературной площадки.

В четырёх математических случаях программа просит сформулировать вопрос ещё раз: слишком большая пробная цифра, слишком маленькая, ноль внутри частного и проверка ответа с остатком. При смене читательской версии с «Чудесного доктора» на рассказ о пятне на чертеже требуется начать поиск заново. На вопрос о странице 10 «Потаённого Леса» программа приводит материал со страницы 9 и сообщает объём сверки лишь в конце. Эти случаи сохранены для сравнения. Качество исходной и дообученной моделей предстоит измерить.

### Повторная проверка подсказок

После первого прогона исправлены четыре сценария деления. При выборе пробной цифры помощник учитывает неполное делимое, делитель и попытку ученика. Если цифру нужно уменьшить, повторное объяснение предлагает убрать одну группу. Место внутри частного сохраняется перед переходом к следующему разряду. Для ответа с остатком проверяются и обратное действие, и допустимость остатка.

В читательском разговоре явное исправление названия снова открывает поиск по каталогу. Обычное уточнение детали по-прежнему сужает предыдущий выбор. Для страницы за пределами доступного фрагмента помощник сначала сообщает объём проверки. Ссылка ведёт прямо на фотографию проверенной страницы.

На тех же 21 контрольных репликах изменились семь математических ответов и три читательских. При переносе запятой помощник показывает число разрядов по исходному делителю и предлагает дописать недостающие нули. Вычисление выполняет ученик. При запросе личного задания помощник объясняет, что посмотреть его можно в кабинете, а в открытом диалоге можно обсудить присланное условие.

Это повторная проверка известных случаев после исправления правил. В отдельных тестах взяты другие числа, названия и номера страниц, проверены нейтральный запрос о назначениях и обычный запрос на подбор упражнений. Для итогового сравнения моделей понадобятся новые отложенные вопросы.
