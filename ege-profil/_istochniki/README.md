# `ege-profil/_istochniki/` — служебные исходники курса

Папка не публикуется: GitHub Pages собирает сайт Jekyll-ом, а пути,
начинающиеся с `_`, Jekyll пропускает. Здесь лежит то, из чего собраны
опубликованные файлы курса, и ворота, которыми они проверяются.

Все команды ниже — из корня репозитория. Node 18+ без зависимостей, кроме
отмеченных «Chromium»: им нужен Playwright (`require("playwright")`) и браузер.
В этом репозитории Playwright объявлен только в `video-worker/package.json`,
поэтому для браузерных ворот укажите его через `NODE_PATH` и путь к Chrome
через `PW_CHROME`, например:

```bash
export NODE_PATH=/путь/к/node_modules            # где установлен playwright
export PW_CHROME="C:/Program Files/Google/Chrome/Application/chrome.exe"
```

### Порядок и прогресс

`sync-data.js` собирает `data.js` = `engine.js` + `engine-legacy.js` + банки
по темам; в каждой теме сначала старые задачи в исходном порядке, потом новые:
`PROBLEMS = [].concat(P_LEGACY_KUB, P_KUB, P_LEGACY_PAR, P_PAR, …, P_RAZV)`.
Поэтому `stereo3.last.<тема>` (позиция в теме) указывает на ту же задачу,
что в опубликованной линейке. Совместимость `stereo3.last` — только по темам:
у марафона без темы (`stereo3.last.all`) порядок иной (сначала Куб, как на
главной), и сохранённая там позиция может открыть другую задачу. Позицию
тренажёр принимает, только если это целое число в пределах темы; дробь, текст,
минус и число за концом темы молча отбрасываются — открывается первая задача
(раньше дробь давала пустой тренажёр). Ключи `stereo3.status`,
`stereo3.last.<тема>` и запись задачи (`st, revealed, attempts, wrong, topic,
updatedAt`) — как в опубликованной линейке.

Чертежи старых задач строит тот же код, что в опубликованной линейке;
движок только равномерно уменьшает их мир в k = 4,15 / 5,6 ≈ 0,741 раза —
до размера новых сцен: при стартовой камере у 53 из 143 старых задач часть
вершин уходила за край кадра (так и в опубликованной линейке). Форма
чертежа и длины в единицах задачи не меняются — это проверяет `legacy-parity.js`
(у 27 задач из его списка `SCENE_FIXED` чертёж исправлен намеренно).
Тела вращения старых задач движок рисует с полупрозрачной стенкой
(`seeThrough`): внутри них ось, радиус, вода и сечения, которые в новой
палитре иначе закрыла бы непрозрачная поверхность.

Панель измерений после верного ответа (или «Решения») подписывает выбранный
отрезок: подписанный — текстом подписи, остальные — `fmtLen(длина на сцене
· unit)` (`trainer.js`, `displayLen`). `unit` — поле старой задачи, чья сцена
нарисована в масштабе k ≠ 1 (длина условия на единицу сцены, unit = 1/k);
у остальных задач его нет, то есть 1. `fmtLen` (`engine.js`, общий для обоих
банков): целое — «6»; если длина x = √m для целого m ≤ 100 000 с допуском
по самой длине |√m − x| ≤ 1e-9·max(1, x) — корень в школьной записи
с вынесенным множителем: «2√2», «2√3», «√5», «3√3»; иначе — до сотых,
с запятой, без хвостовых нулей: «2,5», «3,01». Сотые считаются целым числом
(`Math.round(x·100 + 1e-9)`), без хвостов float: 2,675 → «2,68». Прежний
допуск 1e-6·m на квадрат длины у длин от ≈30 принимал за корень числа,
корнями не являющиеся (для 97 000 длин от 30 до 1000 — 52 905 ложных
«корней», теперь 2); на 10 368 попарных длинах банка старая и новая запись
совпадают все.

## Ворота банка стереометрии

Из корня репозитория:

```bash
cd ege-profil/_istochniki/stereo-bank

node sync-data.js            # data.js собран из исходников → «OK: data.js совпадает…»
node sync-data.js --write    # пересобрать после правки банка (потом — все ворота заново)

node _check.js --all         # структура всех 19 массивов, размер каждого по таблице EXPECTED
                             # (P_LEGACY_KUB 14, P_KUB 13, … P_RAZV 7), итог 288 и 281 без
                             # «Развёрток», id уникальны → «OK: всего 288 = 281 … + 7 …»
node _check.js problems-kub.js P_KUB "Куб" 13                  # один банк
node _check.js problems-legacy-kub.js P_LEGACY_KUB "Куб" 14

for f in verify-*.js; do node "$f" || echo "FAIL $f"; done
                             # новые: «OK N задач, расхождений 0» (и обратная проверка
                             # «модель есть, задачи нет»); старые: маркер *_VERIFY_OK
for f in verify-legacy-*.js; do node "$f" --strict || echo "FAIL $f --strict"; done
                             # то же с --strict: предупреждения — расхождения

node legacy-parity.js        # старые задачи: id, тексты, ответы, порядок = опубликованная
                             # линейка; чертежи — тоже, кроме списка SCENE_FIXED, у которого
                             # на месте отпечатки правки (REQUIRED); unit — только у списка
                             # UNIT; у каждой задачи с построением (142 из 288) построение
                             # что-то добавляет на сцену
                             # (LEGACY_DATA — путь к data.js опубликованной линейки)
node display-scale.js        # подписи = то, что покажет панель измерений → DISPLAY_SCALE_OK

# Chromium (NODE_PATH, PW_CHROME — см. выше)
node render-test.js          # все 288 задач (1280): верный ответ, построение, 0 ошибок
                             # консоли, чертёж при открытии целиком в кадре, нет утечки
                             # памяти видеокарты (живые WebGL-буферы и текстуры)
node render-test.js "Куб" --shots=/tmp/shots-kub               # одна тема + скриншоты
node touch-test.js           # 360 px с касанием: 10 старых + 10 новых задач,
                             # вращение пальцем, щипок только масштабирует, чертёж
                             # в кадре и не под легендой, без горизонтальной прокрутки,
                             # обязательные кнопки есть, видны, ≥ 44 px и не
                             # перекрыты; касание ребра тела со скрытыми буквами
                             # (kub-14) открывает измерение («ребро = …»), ребра
                             # призрака без букв (27061) — нет; касание рёбер вверху
                             # чертежа не меняет задачу, не включает ⟳, не сбрасывает
                             # вид, не сдвигает холст, click не приходит → STEREO_TOUCH_OK
bash topic-run.sh kub P_KUB "Куб"                   # изолированный прогон одного банка
bash topic-run.sh legacy-kub P_LEGACY_KUB "Куб"
```

Пути по умолчанию считаются от расположения скриптов: пакет стереометрии —
`STEREO_ROOT` (по умолчанию `ege-profil/trainers/stereo`). Скриншоты `shots-*`
— рабочие файлы, в репозиторий их не класть. `_frame.js` — общий для
`render-test.js` и `touch-test.js` доступ к сцене и камере тренажёра
(обёртка над `THREE.WebGLRenderer`, сам тренажёр наружу ничего не отдаёт)
и проверка «чертёж целиком в кадре».

## Верификаторы старых задач: `verify-legacy-*.js`

Девять файлов, по одному на тему: `kub`, `par`, `sost`, `priz`, `pir`, `cil`,
`kon`, `shar`, `komb`. Каждый берёт из `PROBLEMS` старые задачи своей темы
(числовой id, всего 143) и ничего не правит. Новые задачи (`kub-01`…)
пропускает — их проверяют `verify-<slug>.js`.

Общее для всех девяти:

- **Голый Node**: только `fs`, `path`, `vm`. Загрузчик `data.js` (песочница
  `vm` с заглушками THREE и DOM) встроен в каждый файл, чужие файлы
  не подключаются. Загрузчик понимает обе линейки:
  - опубликованную `trainers/ege-profile-stereometry-3d` — там `PROBLEMS`
    и `sceneData` глобальные;
  - объединённую — там `module.exports`, а `sceneData` — диспетчер
    к `sceneDataLegacy`.

  Путь задаёт `STEREO_ROOT`, по умолчанию `ege-profil/trainers/stereo`.
- **Состав темы.** Старых задач ровно столько, сколько в опубликованной
  линейке, и id не повторяются. `shar` и `komb` проверяют ещё и порядок:
  старые задачи стоят в теме первыми, в прежнем порядке. От порядка зависит
  ключ `stereo3.last.<тема>`.
- **Ответ — от текста условия, своим кодом.**
  - Формулировка узнаётся шаблоном на весь текст: лишнее или пропущенное
    число не пройдёт. Модель сверяется с ожидаемой для этого id.
  - Числа берутся из `p.cond`.
  - Ответ пересчитывается на координатной модели тела, без формул из разбора:
    выпуклые оболочки, бисекция для обратных задач, численное интегрирование
    и вписанные многоугольники для тел вращения.
  - `p.sol` и `p.hint` не читаются. `p.ans` нужен только для итоговой сверки,
    допуск 1e-9.
  - Если условие не задаёт тело однозначно, ответ считается на нескольких
    телах, в том числе наклонных, и должен совпасть на всех.
- **Данные с рисунка** помечены в коде `ПО РИСУНКУ`. Это все 6 старых
  «Составных тел» (в их условиях нет чисел), 27202–27205 и ориентация
  сосуда 318145 в «Конусе», форма пирамиды 639619 в «Кубе». `pir` берёт
  со сцены только размеры, которых условие не задаёт (метка `СО СЦЕНЫ`).
- **Чертёж** проверяется по выходу `sceneData(p)`, собранному так же, как
  в `trainer.js`: одна точка на имя, последнее тело выигрывает.
  Проверяются вид каждого тела, подписи, отрезок «?», тело построения
  и сечение. Все величины сводятся к одному масштабу k на задачу,
  допуск 1e-6.
- **Поле `unit`** (с 24.09.2026, во всех девяти). Масштаб k — «сцена /
  условие». Если у задачи есть `unit`, он обязан быть равен 1/k (допуск
  1e-6), иначе расхождение: панель измерений показала бы длины не в единицах
  условия; `unit` без масштаба, заданного условием, — тоже расхождение.
  Если `unit` нет, а k ≠ 1, — предупреждение, как раньше (у `par` и в
  «Призме» с числовыми подписями — расхождение).
- **Вывод.**
  - На каждую ошибку — строка `РАСХОЖДЕНИЕ …`, в конце итог
    `<Тема> (старые): задач N, расхождений K`.
  - При K = 0 печатается маркер `LEGACY_<SLUG>_VERIFY_OK`, код выхода 0;
    иначе код 1.
  - Предупреждения на код выхода не влияют.
  - Ключ `-v` печатает строку на каждую задачу.
  - Ключ `--strict` — у всех девяти (с 24.09.2026 и у `par`, `pir`, `shar`,
    `sost`): с ним предупреждения считаются расхождениями. У `kub` и `priz`
    так считаются только дефекты видимости, как раньше.
  - Примечания — сведения, а не дефекты, `--strict` их не трогает: у `par` —
    «ответ одинаков на N телах» (условие не задаёт форму); у `pir` —
    масштаб k ≠ 1 из-за округления размера в задании сцены, когда все
    длины между названными точками панель показывает так же, как при k = 1
    (27184: ребро куба 2,29 ≈ ∛12). Раньше у `pir` это было предупреждение,
    и сверялась только одна длина.
  - `kon`: окружность основания целиком при нарисованной части конуса и точки
    P, Q целого конуса в вырезе — на линейке курса расхождение (движок курса
    их исправил, откат правки должен краснеть), на опубликованной линейке —
    по-прежнему предупреждение (там они есть). Линейку курса верификатор
    узнаёт по `sceneDataLegacy` в экспорте `data.js`.

**Округление размера сцены** (`verify-legacy-priz.js`, модель `vertpoly`).
В опубликованной линейке у 245340 сторона основания в сцене — 2,15: точная
сторона √(8/√3) ≈ 2,14914, округлённая до сотых (так же у 27184 в «Пирамиде»
ребро куба 2,29 ≈ ∛12). В линейке курса у 245340 сторона точная, и эта ветка
верификатора срабатывает только на опубликованной линейке. Округление
считается предупреждением только при двух условиях:

1. сторона ровно равна точной, округлённой до сотых;
2. все 15 расстояний между вершинами тренажёр показывает так же, как
   у точной призмы — сравниваются строки `fmtLen` банка (с 24.09.2026
   с корнями в школьной записи; раньше — до сотых).

Остальные величины сверяются с призмой именно с этой стороной, допуск
прежний (1e-6). Другая сторона (2,16; 2,14; 2,149; 2,2) — расхождение.
Округление, которое видно на экране, — тоже расхождение: при площади 10,5
и стороне 4,92 тренажёр покажет A₁B = 5,76 вместо 5,77.

### `display-scale.js`: подписи и панель измерений в одних единицах

После верного ответа панель измерений подписывает выбранный отрезок: подписанный
— текстом подписи, остальные — `fmtLen(длина на сцене · unit)`. Ворота
проверяют для всех 288 задач, что каждая числовая подпись `[a, b, «число»]`
из `labels` и каждый подписанный отрезок построения равны тому, что панель
показала бы для этого отрезка без подписи. «Число» — «12», «2,5», «√5»,
«2√3». Подпись, записанная не так, как пишет `fmtLen`, но равная по значению
(«√12» из текста условия при «2√3»), — примечание. Кроме того: `unit` — только
конечное положительное число и только у старых задач (сцены новых строятся
в единицах условия). Верность самого значения unit = 1/k проверяют
`verify-legacy-*.js`: у всех 24 задач с `unit` числовых подписей нет (условие
даёт объём или площадь), и сверить его с подписями нельзя. Выносные подписи

стоит на середине радиуса), у старых «Составных тел» их сверяет

ворота находят 676923 (подпись «3» на отрезке длины √3).

`fmtLen` (п. 4 задания владельца): целое → «n»; x = √m (m ≤ 100 000,
допуск по длине 1e-9·max(1, x)) → «2√2», «2√3», «√5»; иначе до сотых. Ни `_check.js`, ни

### Что осталось

- **27184 («Пирамида»)** — ребро куба в сцене 2,29 ≈ ∛12 (k = 1,00025); на

- **324457** — при стартовой камере диагональ BD₁ почти сливается с ребром
  BB₁ (видно после поворота). Не тронуто: ракурс у всех задач общий
  (`trainer.js`, `T.goHome`: θ = −0,65, φ = 1,18; расстояние — не ближе 12,
  по размеру сцены и аспекту холста, то же в кнопке «⌂»), данными задачи
  его не задать; подпись «17» стоит в середине BD₁, и сдвинуть её данными тоже

- У 676923 «?» на PQ (в построении) стоит рядом с буквой O — не правилось.

## Ворота дерева курса (из архива)

```bash
# ссылки, тупики, сироты, внешние домены, ключи прогресса; корень — ege-profil/
python3 ege-profil/_istochniki/patches/check-links.py            # или: check-links.py <корень курса>

# поведенческая проверка пяти доработок архива, 19 проверок (Chromium)
COURSE_ROOT=ege-profil node ege-profil/_istochniki/patches/verify5.js
```

`check-links.py` разрешает относительные `href`/`src` по диску (в том числе
ведущие из курса на сайт, `../trainers/…`) и ищет их и в `<script>`, так что
адрес, собранный в JS-строке, тоже попадает в проверку. Скрипт ничего
не меняет. `verify5.js` открывает страницы по `file://`; скриншоты кладёт
в `SHOTS_DIR` (по умолчанию во временную папку системы).

## Правила

- `js/data.js` линейки руками не правится: правка — в `problems-*.js`,
  затем `node sync-data.js --write` и все ворота.
- Старые задачи (`problems-legacy-*.js`): id, условие, ответ, подсказка,
  решение и порядок не правятся и не переставляются. Чертёж (`scene`,
  `labels`, `construct`) и поле `unit` — только по решению владельца и
  вместе с записью в списки `SCENE_FIXED` / `UNIT` в `legacy-parity.js`.
- Опубликованная линейка `trainers/ege-profile-stereometry-3d/` отсюда
  не правится.
- Машинных абсолютных путей в скриптах нет: всё считается от расположения
  скрипта или задаётся переменными (`STEREO_ROOT`, `COURSE_ROOT`, `LEGACY_DATA`,
  `PW_CHROME`, `SHOTS_DIR`).
